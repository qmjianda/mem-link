## Purpose

提供一个独立、全屏、可直接操作的结构布局编辑工作区，让用户在字节和位两个视图里创建、移动、嵌套和校验布局，同时保持与蓝图其他部分相同的撤销、引用和文档语义。

## ADDED Requirements

### Requirement: 独立设计器页面与入口

结构设计器 MUST 作为全屏、可深链的页面级编辑视图打开，而不是在检查器内展开完整字段表单。入口 MUST 至少包括读结构节点的检查器摘要和嵌套布局的父字段；打开时 MUST 保留原蓝图的选择、视口、滚动位置和撤销历史，关闭后 MUST 回到触发位置并把焦点还给触发控件。页面 MUST 有可访问名称，背景蓝图 MUST 不可聚焦。

打开或进入子布局 MUST 更新 URL 为 `#design/<layoutId>`，嵌套路径 MUST 反映当前布局栈。浏览器后退/前进 MUST 在布局栈与蓝图之间导航；直接打开缺失的布局 MUST 显示可恢复的缺失状态，而不是白屏、猜测或自动跳到第一个布局。

#### Scenario: 从检查器打开并返回

- **GIVEN** 用户选中一个引用 `layout/header` 的读结构节点，并停在某个画布视口
- **WHEN** 用户点击「打开结构设计器」，完成编辑后关闭
- **THEN** 设计器打开时显示 `Header`，关闭后回到原节点与原视口，焦点回到「打开结构设计器」按钮

#### Scenario: 深链与浏览器后退

- **GIVEN** 用户直接用 `#design/header/entry` 打开设计器
- **WHEN** 用户按浏览器后退，再按前进
- **THEN** 后退回到 `Header` 的布局栈，前进回到 `Entry`，文档内容不因导航改变

#### Scenario: 缺失布局有恢复路径

- **GIVEN** URL 指向一个已被删除的布局
- **WHEN** 设计器加载该路由
- **THEN** 显示「布局不存在」状态，并提供返回蓝图和选择其他布局的动作，不自动打开其他布局

### Requirement: 布局列表与生命周期

设计器 MUST 提供布局列表，显示每个布局的名称、长度、字段数和被引用数。用户 MUST 能新建、重命名、复制和删除布局。布局 id MUST 稳定；重命名 MUST NOT 改变 id、字段 id 或已有引用。新建布局 MUST 得到唯一 id 和可编辑的初始字段，或在用户明确选择时创建空布局。复制布局 MUST 生成新的 id，并保持字段内容与内部引用独立。

删除被其他布局、图中节点或启用的 pack 通过 `layoutType` 引用的布局 MUST 被拒绝，并列出引用来源；用户移除引用后才能删除。删除成功 MUST 作为一次可撤销编辑。pack 类型 MUST 只读，不出现在可编辑布局的创建、重命名或删除路径中。

#### Scenario: 新建布局

- **GIVEN** 当前文档已有 `Header` 和 `Entry`
- **WHEN** 用户在布局列表点击「新建」
- **THEN** 生成一个唯一 id 的新布局并进入编辑状态，已有布局和引用不受影响

#### Scenario: 重命名不断开引用

- **GIVEN** `Header.entries` 引用 `layout/entry`
- **WHEN** 用户把 `Entry` 重命名为 `Record`
- **THEN** 引用仍指向同一 id；`Header.entries` 显示新名称，已有节点端口不需要重连

#### Scenario: 删除被引用布局被拒绝

- **GIVEN** `Entry` 被 `Header`、三个读结构节点和一个通过 `layoutType` 引用它的 pack 引用
- **WHEN** 用户尝试删除 `Entry`
- **THEN** 删除被拒绝，界面列出父布局、节点和 pack 来源，并说明先移除引用

### Requirement: 字节视图显示空间关系

字节视图 MUST 以可配置的每行 4/8/16/32 字节显示字节标尺、行偏移和字段块。字段跨行时 MUST 连续分段显示，第一段显示名称与类型，续段明确表示延续。数组字段 MUST 显示元素数量、元素布局和总长度；record 字段 MUST 显示目标布局与总长度；union MUST 用叠层或共享偏移的方式表示并允许字段重叠。未写 `at` 的字段 MUST 标为「自动」，写 `at` 的字段 MUST 标为「锚定」并显示固定偏移。空白字节 MUST 可定位并用于创建字段。没有字段的布局 MUST 显示空状态和创建入口。

#### Scenario: 16 字节布局完整可见

- **GIVEN** 一个 16 字节布局包含三个标量、一个位域组和一个嵌套数组
- **WHEN** 用户打开字节视图
- **THEN** 标尺显示 0–15 的字节位置，每个字段按偏移和长度定位，位域组标出存储单元，数组标出元素数量

#### Scenario: 字段跨行

- **GIVEN** 一个字符串字段从偏移 3 开始、长度 8 字节，当前每行 4 字节
- **WHEN** 用户查看字节视图
- **THEN** 字段在 3、4–7、8–10 处连续分段显示，第一段带名称，续段有清晰的延续标记

#### Scenario: 联合叠层

- **GIVEN** 一个 `union: true` 布局在偏移 0 同时定义 `u32` 和 `f32`
- **WHEN** 用户查看字节视图
- **THEN** 两个字段以共享偏移的叠层显示，不产生普通重叠错误

#### Scenario: 空布局

- **GIVEN** 一个没有任何字段的新布局
- **WHEN** 用户打开字节视图
- **THEN** 显示空状态、可用的类型面板和创建第一个字段的入口

### Requirement: 位视图显示位域组

位视图 MUST 按 `at + unit` 将位域分组为存储单元，显示位标尺、位域条和已占用位。用户 MUST 能切换 1/2/4/8 字节存储单元，拖动位域条移动位偏移，拖动左右边缘改变位宽，添加和删除位域。位序显示（LSB 在左 / MSB 在左）MUST 只影响显示，不改变字段值、校验或文档。位域区间在同一个存储单元内 MUST NOT 重叠；超过存储单元、位宽非法或区间重叠 MUST 被拒绝并指出冲突字段。窄位域 MUST 仍可通过悬停、选中状态和可访问名称识别。没有位域的布局 MUST 显示空状态和创建位域的入口。

#### Scenario: 拖动和缩放位域

- **GIVEN** 一个 2 字节位域组包含 `kind`（bit 0–1）、`active`（bit 2）和 `mode`（bit 3–5）
- **WHEN** 用户把 `mode` 拖到 bit 6 并把右边缘拉到 bit 9
- **THEN** 位域条和字段属性显示新位置与位宽，组占用和文档同步更新

#### Scenario: 切换存储单元

- **GIVEN** 一个 2 字节位域组当前使用 6 位
- **WHEN** 用户把存储单元切换为 1 字节
- **THEN** 组仍使用 1 字节，位标尺变为 8 位；如果成员放不下则拒绝切换并说明需要多少位

#### Scenario: 位域重叠被拒绝

- **GIVEN** `kind` 占 bit 0–1，`active` 占 bit 2
- **WHEN** 用户把 `active` 拖到 bit 1
- **THEN** 拖动预览标出冲突，松手后不写入文档，并提示 `active` 与 `kind` 的重叠区间

#### Scenario: 无位域的空状态

- **GIVEN** 一个只包含标量字段的布局
- **WHEN** 用户切到位视图
- **THEN** 显示「当前布局没有位域」以及切回字节视图或插入位域的入口

### Requirement: 两个视图共享同一布局和选择

字节视图和位视图 MUST 是同一份 `BinaryLayout` 的两个投影。切换视图 MUST NOT 修改文档，MUST 保持当前选中字段或位域组。位域成员在字节视图中属于其位域组；切到位视图 MUST 定位或高亮该成员，切回字节视图 MUST 高亮所属组。选中的字节字段在位视图中 MUST 在「字节字段」区域可识别，并提供切回字节视图的动作。每行字节数、位序、缩放和平移 MUST 是视图偏好，不写入布局或蓝图文档。

#### Scenario: 从位域组切到位视图

- **GIVEN** 用户在字节视图选中 `flags` 位域组
- **WHEN** 用户切到位视图
- **THEN** 该组对应的泳道被选中，组内位域可见，文档没有变化

#### Scenario: 从字节字段切到位视图

- **GIVEN** 用户选中一个 `u32` 字段
- **WHEN** 用户切到位视图
- **THEN** 该字段出现在「字节字段」区域，点击后回到字节视图并保持选中

### Requirement: 字段创建与直接操作

用户 MUST 能从类型面板拖拽字段到空白字节，也 MUST 能通过点击类型后再点击空白格、或通过可见的「插入字段」菜单完成同样的创建。创建 MUST 分配稳定字段 id 和唯一名称；占用、越界、未知目标布局或非法类型 MUST 拒绝并说明原因。

拖动锚定字段 MUST 更新其 `at`。拖动未锚定字段主体 MUST 进入锚定预览，松手后写入 `at`；拖动重排手柄 MUST 只改变声明顺序且不写 `at`。字符串和 bytes 字段 MUST 能通过右边缘改变长度；标量宽度由类型决定，不提供会改变类型的隐式缩放手势。拖动、缩放和重排 MUST 只在松手时提交；预览 MUST NOT 写入文档；非法落点 MUST 回弹且不产生撤销记录。一次手势 MUST 只产生一次可撤销编辑；Escape MUST 取消未提交手势。多选拖动 MUST 要么整体合法提交，要么明确拒绝，不得部分移动。

#### Scenario: 拖入新字段

- **GIVEN** 一个 16 字节布局在偏移 8–11 有空闲字节
- **WHEN** 用户把 `u32` 类型拖到偏移 8
- **THEN** 创建名称唯一的 `u32` 字段，`at` 为 8，选中该字段，产生一次可撤销编辑

#### Scenario: 拖动自动字段会锚定

- **GIVEN** `count` 没有 `at`，当前推导偏移为 4
- **WHEN** 用户拖动它的主体到偏移 8
- **THEN** 松手后 `count.at` 写为 8，界面标为锚定；撤销一次回到自动偏移 4

#### Scenario: 重排手柄只改顺序

- **GIVEN** `a` 和 `b` 都没有 `at`，当前偏移为 0 和 2
- **WHEN** 用户拖动 `b` 的重排手柄到 `a` 之前
- **THEN** 字段顺序变为 `b, a`，两者仍没有 `at`，偏移按新顺序重算

#### Scenario: 非法落点回弹

- **GIVEN** 偏移 4 已有 `u32` 字段
- **WHEN** 用户把另一个 4 字节字段拖到偏移 4
- **THEN** 预览显示冲突，松手后字段回到原位置，文档和撤销历史都不变

#### Scenario: Escape 取消手势

- **GIVEN** 用户正在拖动一个锚定字段
- **WHEN** 用户按 Escape
- **THEN** 拖动取消，字段保持原偏移，不产生撤销记录

#### Scenario: 无拖动的插入路径

- **GIVEN** 用户只使用键盘或点击
- **WHEN** 用户通过「插入字段」菜单选择类型和偏移
- **THEN** 创建结果与拖拽创建相同，并收到成功或失败的文字反馈

### Requirement: 选择、检查器与字段表

设计器 MUST 维护单一主选中，并允许 Ctrl/Cmd+点击、Shift+范围选择和 Ctrl/Cmd+A 形成多选。多选 MUST 支持删除、复制/粘贴、重复和批量锚定/恢复自动；混合属性 MUST 显示为混合值，不得显示任一成员的假值。选中 MUST 在画布、位域条、字段表和检查器之间同步。检查器 MUST 只编辑当前选中项；无选中时显示布局属性、长度、被引用和整体校验。底部字段表 MUST 显示声明顺序、名称、类型、偏移、大小或位宽、自动/锚定和错误状态，并支持键盘行导航、定位到画布和 F2 改名。状态栏 MUST 显示总长、已用/空闲、字节重叠、位域重叠、字段数和当前选择。

#### Scenario: 三处选中同步

- **GIVEN** 用户在字节视图点击 `count`
- **WHEN** 字段被选中
- **THEN** 字段表对应行高亮，检查器显示 `count` 的属性，状态栏显示其偏移

#### Scenario: 多选删除

- **GIVEN** 用户按 Ctrl/Cmd+点击选中三个标量字段
- **WHEN** 用户按 Delete 并确认
- **THEN** 三个字段在一次编辑中删除，一次撤销恢复全部三个

#### Scenario: 混合属性

- **GIVEN** 多选中的字段有不同字节序
- **WHEN** 检查器显示字节序
- **THEN** 显示「混合」而不是某一个字段的值；修改后才统一应用到全部选中字段

### Requirement: 嵌套布局与引用影响

record 和 array 字段 MUST 能进入目标布局；面包屑 MUST 显示完整嵌套路径并支持返回。子布局修改 MUST 立即更新父布局的字段长度、自动偏移和派生长度，锚定字段 MUST 保持原偏移。设计器 MUST 显示布局被哪些父布局、图中节点和 pack 引用；修改共享布局时 MUST 明确提示影响范围。选择嵌套目标时 MUST 阻止成环，并指出会形成环的路径。pack 类型 MUST 只读，不能在设计器内编辑。

#### Scenario: 子布局变长更新父布局

- **GIVEN** `Header.entries` 引用一个 4 字节的 `Entry`，后面有一个锚定字段
- **WHEN** 用户在 `Entry` 中增加 2 字节字段并返回 `Header`
- **THEN** `entries` 的长度变为 6 字节，锚定字段保持原偏移，父布局派生长度更新

#### Scenario: 阻止循环引用

- **GIVEN** `A` 包含一个引用 `B` 的字段，`B` 还没有引用 `A`
- **WHEN** 用户尝试让 `B` 引用 `A`
- **THEN** 选择被拒绝，界面指出 `A → B → A` 的循环路径

#### Scenario: 共享布局显示引用

- **GIVEN** `Entry` 被 `Header` 和两个读结构节点引用
- **WHEN** 用户打开 `Entry`
- **THEN** 检查器显示父布局和节点引用数，修改时提示会影响这些入口

### Requirement: 删除与引用安全

删除字段前 MUST 检查它是否被图中节点或连线使用。被使用时 MUST 显示受影响的节点和端口数量，并允许取消。用户确认后 MUST 删除字段并把缺失连线保留为可定位问题，MUST NOT 静默改接到同名字段或自动删除节点。删除被其他布局、图中节点或 pack 引用的布局 MUST 被阻止并列出引用来源；删除布局本身 MUST 作为一次可撤销编辑。

#### Scenario: 删除已接线字段

- **GIVEN** `Header.count` 已连接到两个下游节点
- **WHEN** 用户删除 `count`
- **THEN** 界面先列出受影响的节点和端口；确认后字段删除，相关连线变成可定位的缺失端口问题，撤销一次恢复字段

#### Scenario: 删除未引用字段

- **GIVEN** 一个字段没有任何引用
- **WHEN** 用户删除它
- **THEN** 立即删除并产生一次可撤销编辑，不弹出无意义的确认

### Requirement: 校验与诊断

所有布局修改 MUST 在提交前经过与 `compileLayout` 相同的几何和引用校验。字段重名、越界、非联合字段重叠、位域区间重叠、未知或循环嵌套、非法数组数量、非法位宽、长度覆盖小于内容 MUST 阻止提交并指出字段。设计器 MUST 提供问题列表；点击问题 MUST 选中并定位到对应字段和视图。打开一个已经无效的布局 MUST 显示错误和可修复状态，不得崩溃；修复模式 MUST 允许提交减少或保持问题集合的修改，但 MUST NOT 引入新的错误类别；有效布局 MUST NOT 接受任何无效候选。其他读取节点 MUST NOT 按部分字段静默继续。被多处引用、显式长度覆盖等警告 MUST 可见但不阻止合法编辑。

#### Scenario: 非法修改被阻止

- **GIVEN** 一个非联合布局的字段结束于偏移 8
- **WHEN** 用户把另一个字段移动到会与其重叠的位置
- **THEN** 提交被拒绝，冲突字段被定位，文档保持上一有效版本

#### Scenario: 点击问题定位

- **GIVEN** 字段表显示一个「引用缺失」错误
- **WHEN** 用户在问题列表点击该错误
- **THEN** 设计器选中对应字段，必要时切到合适的视图并滚动到可见位置

#### Scenario: 打开无效布局

- **GIVEN** 文档中已有一个因外部编辑而无效的布局
- **WHEN** 用户打开设计器
- **THEN** 设计器显示问题列表和字段级错误，用户仍能修复引用或删除字段，页面不崩溃

#### Scenario: 逐步修复无效布局

- **GIVEN** 一个布局同时有缺失引用和字段越界两个错误
- **WHEN** 用户先修复缺失引用，布局仍有越界错误
- **THEN** 这次修复可以提交且问题数减少；若用户随后引入第三个新错误，则提交被拒绝

### Requirement: 会话历史与退出

设计器编辑 MUST 立即进入文档历史，不引入第二份草稿或保存弹窗；关闭设计器 MUST 保留已提交修改。一次手势、一次字段表提交和一次声明导入 MUST 各为一次撤销步骤。文本输入 MUST 使用本地草稿，在 blur 或 Enter 时提交，Escape 还原，不得逐键写入历史。撤销/重做 MUST 与全局历史一致，新编辑 MUST 清空重做。

设计器打开时 MUST 记录会话起点，并提供「撤销本次打开后的全部修改」动作；没有修改时该动作禁用。执行该动作 MUST 恢复会话起点并产生一次可撤销编辑。关闭、浏览器后退和 Escape 退出 MUST NOT 静默丢弃修改，也不要求用户在“保存/不保存”之间选择。

#### Scenario: 一次拖动一次撤销

- **GIVEN** 用户拖动一个字段并成功落下
- **WHEN** 用户按一次 Ctrl/Cmd+Z
- **THEN** 字段回到拖动前的偏移和锚定状态，不需要多次撤销

#### Scenario: 文本输入不逐键入历史

- **GIVEN** 用户把字段名从 `count` 改为 `total`
- **WHEN** 用户输入并在 blur 时提交
- **THEN** 只产生一次改名编辑；输入过程按 Escape 则恢复 `count`

#### Scenario: 撤销本次打开后的全部修改

- **GIVEN** 用户在设计器中做了多次字段和位域修改
- **WHEN** 用户点击「撤销本次打开后的全部修改」并确认
- **THEN** 布局回到打开时的状态，产生一次可撤销编辑，之前的文档历史仍保留

#### Scenario: 关闭保留修改

- **GIVEN** 用户在设计器中修改了共享布局
- **WHEN** 用户点击「完成」关闭设计器
- **THEN** 修改保留在文档和自动缓存中，回到蓝图后仍可全局撤销

### Requirement: 视图导航、缩放与性能

设计器 MUST 支持 50%–200% 缩放、适应宽度、按住空格或中键平移、Ctrl/Cmd+滚轮缩放，并在缩放或平移后保持选中项可见。缩放、平移、每行字节数、位序和表格展开状态 MUST NOT 修改布局或蓝图文档。拖拽预览 MUST 局部更新，不得在每个 pointermove 重算整份布局或重建整棵画布；在 128 个字段、嵌套布局和位域组的参考数据下 MUST 保持可交互。

#### Scenario: 缩放和平移

- **GIVEN** 一个 128 字节布局在当前窗口只能显示一部分
- **WHEN** 用户缩放、平移并点击「适应」
- **THEN** 字段块与标尺同步缩放/移动，选中字段仍可见，文档没有变化

#### Scenario: 大布局拖动

- **GIVEN** 一个包含 128 个字段的布局
- **WHEN** 用户拖动其中一个字段
- **THEN** 预览跟随指针更新，不出现持续卡顿，松手后只提交一次

### Requirement: 键盘、焦点与可访问性

设计器 MUST 提供完整键盘路径：Tab/Shift+Tab 在区域和字段间移动，Enter 选择或进入嵌套布局，F2 改名，Delete 删除，方向键移动字段或位域，Shift+方向键加速，Alt+方向键调整大小，Ctrl/Cmd+Z 撤销，Ctrl/Cmd+Shift+Z 重做，Ctrl/Cmd+C/V/D 复制/粘贴/重复，Ctrl/Cmd+A 全选。工具栏或菜单 MUST 提供与拖动等价的点击路径。Escape MUST 按「取消手势 → 关闭浮层 → 返回父布局 → 退出设计器」的顺序只处理最上层。输入法组合期间的 Enter、方向键和 Escape MUST NOT 触发应用命令。焦点 MUST 可见；画布字段、位域条和表格行 MUST 有可访问名称、选中状态和错误描述；颜色 MUST NOT 是唯一的状态指示；减少动态偏好 MUST 被尊重。

#### Scenario: 键盘完成移动

- **GIVEN** 用户用 Tab 聚焦一个字段并按 Enter 选中
- **WHEN** 用户按方向键和 Alt+方向键
- **THEN** 字段按步长移动或调整大小，检查器和状态栏同步，操作可撤销

#### Scenario: 输入法不触发命令

- **GIVEN** 用户正在字段名输入框中使用输入法组合中文
- **WHEN** 用户按 Enter 或 Escape
- **THEN** 输入法组合优先处理，不触发提交、退出或返回布局

#### Scenario: Escape 分层

- **GIVEN** 用户位于 `Header → Entry` 且没有打开浮层
- **WHEN** 用户按 Escape
- **THEN** 只返回 `Header`；再次按 Escape 才退出设计器

### Requirement: 导入、导出与模板

设计器 MUST 提供「粘贴声明生成布局」，复用 `layout-authoring` 已定义的声明子集；预览必须显示解析结果和逐行诊断，失败时不得导入半份布局，成功时一次提交。设计器 MUST 提供将当前布局导出为 pack 类型源码的入口，并遵循现有导出规则。设计器 MUST 提供表头、位域、嵌套数组和池下标链表等模板；模板只生成文档布局，不执行输入。所有导入 MUST NOT 执行用户提供的代码。

#### Scenario: 粘贴声明生成多个布局

- **GIVEN** 用户粘贴包含 `Header` 和 `Entry` 的声明
- **WHEN** 用户预览并确认导入
- **THEN** 两个布局一次写入，`Header.entries` 引用 `Entry`，一次撤销恢复导入前状态

#### Scenario: 声明有错不导入

- **GIVEN** 声明中第二个字段引用了未知类型
- **WHEN** 用户尝试导入
- **THEN** 显示行号和未知类型，文档保持导入前状态

#### Scenario: 模板插入

- **GIVEN** 用户在设计器中打开「模板」
- **WHEN** 用户选择「位域」模板
- **THEN** 生成一个包含具名位域的布局，字段可继续编辑，不执行任何脚本

### Requirement: 空状态与恢复

无布局、无字段、无位域、布局缺失、布局无效和引用目标缺失时，设计器 MUST 显示明确的空状态或错误状态，并提供下一步动作。用户 MUST 能返回蓝图、创建布局、插入字段、切回字节视图或修复引用。设计器 MUST NOT 用白屏、伪造空结构或静默回退到同名类型来处理这些状态。

#### Scenario: 没有任何布局

- **GIVEN** 文档中还没有布局
- **WHEN** 用户打开设计器
- **THEN** 显示空状态，提供新建布局、粘贴声明和返回蓝图三个入口

#### Scenario: 引用目标缺失

- **GIVEN** 一个 record 字段引用的布局已被删除
- **WHEN** 用户打开父布局
- **THEN** 该字段标为错误，检查器提供重新选择目标或删除字段的动作，页面其余部分仍可使用
