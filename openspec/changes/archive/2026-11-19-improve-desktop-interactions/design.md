## Context

- `src/bp/BlueprintApp.tsx` 启动时回落到示例，`resetDemo` 和 `onOpenDoc` 复用会清空历史的 `resetDoc`，自动保存同时用 `markSaved` 标记历史。检查「当前历史游标是否已保存」无法判断另一张图是否可以覆盖唯一的工作草稿。
- `src/bp/persist.ts` 的 `TRIMMED` 已与正常写入分开，但顶栏只把 `NO_STORAGE` 和 `TOO_LARGE` 当成降级；裁剪反馈只出现于限时通知。`src/bp/history.ts` 的保存游标在撤销后重新编辑时可能指向另一份快照。
- `src/core/mem.ts` 的 HEX 读取以正则扫出匹配的字节，无法判断哪些字符被跳过。`BlueprintApp.tsx` 的 `onDrop` 找到 `.json` 或 `.ts` 后立即返回，未处理同批其余文件。
- `FileEditor`、`ByteProbe` 和跟随窗口已分别具备选中字节、标量试读、创建节点的最小能力；缺少的是共享选中上下文、保留设置，以及能直接发现的入口。`QuickAdd`、`GraphSearch`、`FollowPicker` 等各自监听全局键盘事件，浏览器焦点和列表内部高亮可以分叉。

## Goals / Non-Goals

**Goals:** 工作区替换、缓存和导出都有可验证结果；试读不会修改图，转成解析时与预览一致；常见操作的焦点与实际执行目标一致。

**Non-Goals:** 不变更当前蓝图格式、节点 ID、类型相容规则、pack API 或脚本信任策略。不增加 Web 专用存储依赖，也不把整个画布改写成全新的可访问组件系统。

## Decisions

### 1. 一个工作草稿，一个示例临时副本

继续使用单文档编辑器。工作状态包含文档、历史、选择、视口及相关问题诊断；进入示例时保存工作会话快照，并清楚标明正在编辑临时副本。示例可导出，但不写工作草稿。返回工作图时恢复工作会话及焦点；不把示例切换压入图编辑的撤销栈。这样比用另一个浏览器标签打开同一 HTML 可控，也避免引入完整的多文档管理。

启动优先恢复当前格式合法草稿；否则显示空白，显式提供导入和示例入口。错误或不受支持的草稿不因首次渲染空白界面被自动覆盖；不延用旧示例识别分支。现有缓存键和文件格式保持不变。

「新建」和「打开」共用工作区替换动作，即使当前工作已经缓存，也必须先确认替换非空工作区。确认界面明确「取消」「导出当前图」「替换」；导出动作本身不意味着许可替换。打开文件先做文档形状检查，确认后使用现有可信 pack 加载策略，解析或加载失败不改当前会话。异步操作绑定发起的工作区与请求；过时的导入结果不能提交到随后打开的图。

### 2. 三种信息分别跟踪：当前快照、缓存结果、导出结果

把「草稿是否最新」绑定到实际文档快照，而不是历史数组位置。合并编辑、撤销后改写 redo 分支、历史已裁剪三种情况都不能把不同快照认成已缓存。只对实际写入的快照更新缓存状态，并防止旧会话的定时器在切换后写入。`TRIMMED` 保留具体来源清单，以便顶部状态展开后显示哪些转储未随草稿恢复；重开后继续用已记录的来源元数据引导重载。

工具栏的导出和 `Mod+S` 走同一入口；已有 `Mod+Shift+E` 可作为同一动作的别名，快捷键帮助和按钮提示由命令口径生成。导出前识别未载入的来源；如果用户确认导出不完整的图，不改变其缺失状态。浏览器下载只报告「已发起导出」，失败保留可恢复的草稿。保留现有 2 MiB 草稿预算和独立文件导出，不在本轮换资产存储。

### 3. 明确输入格式，批量拖放一次决定目标

`parseHexText` 改为按行分类并消费完整标记：裸 HEX、空白分隔字节或 `hexdump -C`。保留可识别的大小写和标准格式；只在识别出带地址转储后将末尾纯地址行作为终止偏移，并检验与已读长度相符。用精确整数检查地址列及连续性；地址列只用于验证，不默默替换转储节点的映射基址。含 `*` 的压缩、不完整字节、格式混杂和跳跃地址返回行列与原因。与「尽量提取看起来像 HEX 的字符」相比，此做法宁可让用户修复文本，也不产生错误转储。

在文件读取前先分类整个投放批次，复用相同的单文件导入服务。工作区替换至多执行一次；蓝图打开或取消决定剩余项的目标。保留当前可识别转储与 pack 的输入类型。汇总每项结果：已导入、已跳过及理由、失败及原因；不能由第一个成功项吞掉其余项。已载入来源的替换先验证输入，错误时保留原字节。

### 4. 在选中字节旁区分「看」与「记录」

在 `FileEditor` 中让点选、地址跳转共用一个选中位点，包含 `BufferValue` 来源引用、精确绝对地址和范围内偏移。`ByteProbe` 默认可见，沿用 `scalarRead` 做即时预览，类型与字节序只存于界面。直接「添加读数值节点」使用显式配置，不再让上次新增节点的默认值覆盖本次预览参数；将创建和来源连线走一次图提交。保留「在此地址解析」作为选择其它读取方式的入口。

来源解析先按现有映射身份和范围校验，再向界面交付「可直接使用」「需要选来源」或「不可用」。受限范围和已绑定地址不参与跨映射回退；尚未绑定的地址可以由用户在覆盖该地址的来源中选择，选中后把所选来源明确传递到新增节点。显示文件名、映射基址及可区分的节点名称等；同源限制与 64 位地址行为不变。优先显示读数值、读结构等常见入口，保留已有可靠类型推荐；高级指针链折叠但已配置时可见。禁止更改底层节点职责来减少界面步骤。

### 5. 对话框共用焦点规则，命令保留原生行为

优先使用原生模态 `dialog`（需要时复用现有浮层样式），统一记录触发元素、进入焦点、只让顶层响应取消，并在触发元素失效时恢复到画布、检查器或当前步骤的合理控件。用共享外壳，而不是为五个窗口分别添加全局 Tab 捕获逻辑。嵌套跟随保留结构浏览会话及当前行；保留可触达的取消入口。上下文菜单仍可作为快捷入口，不将它伪装为普通模态。

搜索候选使用同一项标识同步浏览器焦点、列表高亮及执行目标。搜索输入只处理自身的方向键和确认；已聚焦的按钮、下拉和表单使用原生按键行为。组合输入正在编辑时跳过应用命令，避免确认中文候选时触发节点创建或取消窗口。依托现有点击两个端口的行为，为端口和检查器提供明确的起线、接入、替换及取消操作，键盘与鼠标复用 `canConnect` 和原提交路径；大量动态端口优先通过当前节点或按名称查找，不让 Tab 顺序遍历整张大图。

## Risks / Trade-offs

- **自动缓存与切换有时序竞争** → 在真实浏览器覆盖编辑后立即进示例、等待防抖、打开失败或取消、同一历史游标换快照；同时验证失败不覆盖上一份可用缓存。
- **严格 HEX 校验会拒绝曾被容错接受的内容** → 对标准输入提供测试样本和清晰错误位置；`*` 等不支持形式告诉用户如何导出未压缩文本。
- **共用对话框可能改变现有 Enter 快捷路径** → 单独回归搜索框确认、候选按钮确认、偏移链和下拉控件、中文输入法、嵌套返回；针对 `file://` 生产构建验收。
- **来源选择可能让人误以为能重定位已绑定地址** → 只为尚未确定映射且有合法候选的情形显示选择器；保留明确的类型、范围与来源拒绝原因。

## Migration Plan

1. 先保护草稿与示例边界、完善缓存与导出反馈，再收紧 HEX 和批量导入。
2. 接顺选中字节、试读、来源选择和落图，并统一这条路径上的鼠标与键盘行为。
3. 更新使用说明与真实浏览器回归，保留当前 `memlink-blueprint/2`、现有 `.bp.ts` 与节点工作流。不删除旧格式文件或旧缓存；不写新的版本迁移。
