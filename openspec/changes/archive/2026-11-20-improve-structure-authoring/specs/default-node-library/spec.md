## MODIFIED Requirements

### Requirement: 固定结构布局可在蓝图中定义并复用

用户 MUST 可在界面定义具名布局与字段名、类型和必要的宽度、字节序，不依赖 `.bp.ts` 或执行自定义代码。布局 MUST 使用一套几何规则：字段写了 `at` 就固定字节偏移，未写就按声明顺序自动排布；结构长度默认由最终游标推导，可显式覆盖但不能小于内容。布局 MUST 支持嵌套 `record`/`array`（只引用其他布局）、联合共享偏移、枚举显示映射和具名位域，并 MUST 随图保存、可由多个节点引用；字段改名或布局改名 MUST 保留有效连线。读结构 MUST 从指定起点按布局读取一条记录，输出具名、可接线的字段；嵌套记录 MUST 输出可继续展开的 `instance`，嵌套数组 MUST 输出可继续取项的 `list`；检查器 MUST 能定位字段对应的原始字节。结构选择器 MUST 同时提供文档布局和已启用 pack 的类型；选择 pack 类型时 MUST 无需添加该 pack 的结构节点即可读取，并与 pack 节点的字段值、转换和结构长度一致。无效布局、字段越过声明边界、非联合字段重叠、嵌套引用缺失/成环、字段无法读取 MUST 有明确诊断，且不得输出伪造字段或静默回退到同名类型。

#### Scenario: 修改共享布局后保存重开

- **GIVEN** 一张无 pack 的图中两个读取节点引用同一个布局，`count` 字段已接线
- **WHEN** 用户修改字段显示名，保存并重开
- **THEN** 两节点仍引用该布局，原有连线仍绑定同一个字段，点击字段能定位原字节

#### Scenario: 插入未锚定字段后所有引用同步

- **GIVEN** 一个布局被两个读取节点引用，字段按顺序自动排布
- **WHEN** 用户在中间插入一个字段并重新求值
- **THEN** 两个节点都按新偏移读取，结构长度与字段端口同步更新

#### Scenario: 表头布局嵌套表项数组

- **GIVEN** `Header` 布局包含一个引用 `Entry` 布局的定长数组字段
- **WHEN** 用户用“读结构”读取 `Header`，再把数组输出接到“按下标取项”
- **THEN** 能取到对应 `Entry` 的字段，检查器能定位该元素的原始字节

#### Scenario: 联合布局读取同一段字节

- **GIVEN** 一个 `union: true` 的布局在偏移 0 同时声明 `u32 asU32` 与 `f32 asF32`
- **WHEN** 用户用“读结构”读取该布局
- **THEN** 两个字段都从偏移 0 读取，互不覆盖，检查器能分别显示整数与浮点结果

#### Scenario: 不写 pack 也能用 pack 类型

- **GIVEN** 一张只含转储和“读结构”的图，已导入一个声明了 `Header` 的 pack
- **WHEN** 用户把“读结构”的结构选择器切到该 pack 的 `Header`
- **THEN** 节点直接输出 `Header` 字段，不需要新增或连接 pack 的结构节点
