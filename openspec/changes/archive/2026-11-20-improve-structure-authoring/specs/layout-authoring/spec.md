## Purpose

让用户在不写脚本、不执行自定义代码的前提下，在蓝图上快速、准确地定义可复用的结构布局，并覆盖嵌套布局、定长数组和位域。

## ADDED Requirements

### Requirement: 粘贴声明生成布局

布局编辑器 MUST 提供“粘贴声明生成布局”，接受文档化的 C / TypeScript 风格结构声明子集，一次可生成一个或多个布局。该子集 MUST 至少支持 `struct`、`union`、`typedef struct {...} Name;`、字段名与类型、定长数组、位域（`type name : width`）、`//` 与 `/* */` 注释，以及引用同一段声明或当前文档中已有的布局。导入 MUST 先展示解析结果与逐行诊断，用户确认后才写入文档；解析失败 MUST NOT 只导入一部分。生成过程 MUST NOT 执行声明中的任何代码。解析器 MUST 只做紧凑排布；需要 C ABI 填充时，由用户事后给字段填写 `at` 偏移，不提供第二套对齐模式。

#### Scenario: 粘贴两个结构并建立引用

- **GIVEN** 用户粘贴包含 `struct Header { uint16_t count; Entry entries[4]; };` 与 `struct Entry { uint16_t id; uint16_t value; };` 的声明
- **WHEN** 用户确认导入
- **THEN** 文档得到两个布局，`Header.entries` 引用 `Entry` 数组，字段偏移按声明顺序紧凑排布

#### Scenario: 位域与注释被正确读取

- **GIVEN** 粘贴 `struct Flags { unsigned kind : 2; // 类型\n unsigned active : 1; };`
- **WHEN** 用户确认导入
- **THEN** 两个位域落在同一存储单元，注释不进入字段名，检查器能显示各自数值

#### Scenario: 声明有错时不留下半份布局

- **GIVEN** 粘贴的声明中第二个字段使用了未知类型
- **WHEN** 用户确认导入
- **THEN** 诊断指出该字段所在行与未知类型，文档保持导入前的布局不变

### Requirement: C 构造只保留解析后的内存布局

布局 MUST 用最小原语表示 C 构造：命名嵌套结构用 `record` 引用另一布局，匿名嵌套结构或联合 MUST 生成稳定的布局名后再引用；`union` MUST 用布局级 `union: true` 标记，字段通过相同 `at` 共享偏移，非联合布局的字段重叠 MUST 报错；枚举 MUST 表示为整数字段加 `values` 映射，只影响显示，不改变值或宽度；粘贴 `enum` 时必须能确定底层整数宽度（声明中显式给出，或映射到已知的定宽整数），无法确定时报错，不按默认 `int` 猜测。宏 MUST NOT 展开：`#define`、条件编译和影响偏移/数量/长度的宏值 MUST 在粘贴前解析成具体数字；解析器遇到未知标识符 MUST 报错并指出行号，不得猜测或执行。`#pragma pack`、`__attribute__((packed))` 与编译器自然对齐 MUST NOT 自动推断；需要对齐或填充时由用户给字段写 `at`，解析器只做紧凑排布。指针 MUST 表示为固定宽度整数并使用 `role: address`，不自动解引用。

#### Scenario: 联合映射为共享偏移

- **GIVEN** C 声明 `union Value { uint32_t asU32; float asF32; };`
- **WHEN** 粘贴导入为布局
- **THEN** 生成一个 `union: true` 的布局，两个字段都在偏移 0、宽度 4，读取时共享同一段字节

#### Scenario: 枚举只改变显示

- **GIVEN** 布局字段 `state` 是 `u16`，并配置 `values` 为 `{ 0: 'Idle', 1: 'Run' }`
- **WHEN** 读到值 1
- **THEN** 检查器显示 `Run`，端口值和下游计算仍使用整数 1

#### Scenario: 宏未解析时明确失败

- **GIVEN** 粘贴的声明使用 `Entry entries[COUNT];`，但 `COUNT` 不在同一段声明或已有布局中定义
- **WHEN** 用户确认导入
- **THEN** 报错指出 `COUNT` 所在行与未知标识符，不生成任何布局

#### Scenario: 对齐必须显式

- **GIVEN** C 声明使用 `#pragma pack(1)` 或自然对齐
- **WHEN** 粘贴导入为布局
- **THEN** 解析器按紧凑顺序生成字段；用户需要 ABI 填充时给后续字段填写 `at`，不出现隐式对齐开关

### Requirement: 布局只有一套几何规则

布局字段 MUST 按声明顺序处理：未写 `at` 的字段从当前游标开始，字段结束后游标推进到字段末尾；写了 `at` 的字段固定在指定字节偏移，若其结束位置超过当前游标则游标推进到该结束位置。结构长度 MUST 等于最终游标；布局可显式覆盖长度，但覆盖值 MUST 不小于最终游标。布局 MUST NOT 提供自动/手动模式开关，也不得为同一字段提供第二套位置参数。插入、删除、重排字段或改变字段宽度 MUST 使未锚定的后续字段与推导长度立即更新；带 `at` 的字段 MUST 保持原偏移。字段改名 MUST NOT 改变字段 id。

#### Scenario: 在中部插入字段

- **GIVEN** 一个布局依次包含 `u16 a`、`u32 b`，两者都没有 `at`
- **WHEN** 用户在 `a` 与 `b` 之间插入 `u16 c`
- **THEN** `c` 偏移为 2、`b` 偏移为 4、结构长度变为 8；所有引用该布局的节点在下一次求值时使用新偏移

#### Scenario: 锚点字段不被重排

- **GIVEN** 一个布局依次包含 `u8 a`、`u32 flags`（`at` 为 16）、`u16 tail`
- **WHEN** 用户在 `a` 后插入 `u16 b`
- **THEN** `flags` 仍在偏移 16、`tail` 仍在偏移 20，结构长度为 22

#### Scenario: 显式长度不能小于内容

- **GIVEN** 一个布局的最后一个字段结束于偏移 12
- **WHEN** 用户把布局长度覆盖为 8
- **THEN** 编辑器提示长度小于字段结束位置，修改不写入文档

### Requirement: 嵌套布局与定长数组

布局字段 MUST 能引用另一份布局，形成 `record` 字段；MUST 能定义定长 `array` 字段，元素可以是标量或布局，并可指定元素数量。布局嵌套 MUST 只引用布局，不直接嵌入 pack 类型；pack 类型复用发生在“读结构”的根结构选择和 pack 的 `layoutType`。嵌套引用 MUST 使用稳定 id，显示名改变不得断开引用。读取记录时 MUST 输出嵌套字段对应的 `instance` 或 `list` 值，使元素解析、按下标取项和结构树能继续展开。嵌套引用成环、目标缺失或数组越界 MUST 报错，不得返回空记录。

#### Scenario: 表头引用表项数组

- **GIVEN** `Header` 布局包含一个引用 `Entry` 布局、数量为 4 的数组字段 `entries`
- **WHEN** 用“读结构”读取 `Header`
- **THEN** `entries` 输出一个包含 4 项的 `list`，每项保留自己的地址和 `Entry` 字段，结构树可以逐项展开

#### Scenario: 改名不断开引用

- **GIVEN** 两个布局通过稳定 id 相互引用
- **WHEN** 用户修改被引用布局的显示名
- **THEN** 引用仍然有效，已有读取节点和连线不需要重连

### Requirement: 位域是具名可接线字段

布局 MUST 支持位域：字段声明存储宽度（`unit`，1/2/4/8 字节）、组内位偏移（`bit`）和位宽（`width`），多个位域可共享同一存储单元。未写 `bit` 的位域 MUST 按字段顺序接在当前位组之后；写 `unit` 或前一个字段不是位域时 MUST 开始新位组；位组结束时游标 MUST 推进到存储单元末尾。位组超过存储宽度或 64 位 MUST 报错。每个位域 MUST 作为独立具名字段输出，检查器 MUST 能定位到它覆盖的字节。

#### Scenario: 状态字段拆成多个位段

- **GIVEN** 一个布局在偏移 4 定义 2 字节状态字段，其中 `kind` 占位 0–1、`active` 占位 2、`mode` 占位 3–5
- **WHEN** 读取该布局
- **THEN** 三个位段分别输出数值，检查器点击任一位段都高亮偏移 4 起的 2 字节

#### Scenario: 位宽溢出被拒绝

- **GIVEN** 一个 1 字节位组已经使用 7 位
- **WHEN** 用户再添加 2 位的位域
- **THEN** 编辑器提示该组需要 9 位、超过 1 字节，修改不写入文档

### Requirement: 布局编辑即时校验且共享

每次布局修改 MUST 先按当前引用关系校验：字段名重复、字段越界、未知嵌套引用、循环引用、位宽非法或数组数量非法时 MUST 阻止该次修改并指出字段。有效修改 MUST 随图保存、被所有引用节点共享，并作为一次可撤销编辑提交；读取节点在下一次求值时使用新布局。无效布局 MUST NOT 让引用节点按部分字段或旧字段静默继续读取。

#### Scenario: 越界修改被阻止

- **GIVEN** 一个结构长度为 8 的布局，最后一个字段结束于偏移 8
- **WHEN** 用户把该字段宽度改为 4 字节
- **THEN** 编辑器提示字段超出结构范围，修改不写入文档，其他引用节点仍使用上一有效版本

#### Scenario: 共享修改只提交一次

- **GIVEN** 图中两个读取节点引用同一布局
- **WHEN** 用户修改一个字段的显示名
- **THEN** 两个节点同时看到新名称，撤销一次即可恢复旧名称
