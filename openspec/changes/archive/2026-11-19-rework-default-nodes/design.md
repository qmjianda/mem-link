## Context

`src/bp/builtins.ts` 的同一注册表既服务求值，也被 `Palette.tsx`、`QuickAdd.tsx` 和 `follow.ts` 用来列出新节点；`follow.ts` 还有一份额外的节点 ID 筛选。`BlueprintApp.tsx` 的「新建 pack」只编译 `packops.ts` 提供的固定模板。

当前 `readInt` 把 `readBig` 的结果转成 `number`，`Memory.base` 与跟随地址也采用 `number`。旧 `arrayread` 的结果是截短的显示字符串，不能接到负责取项的节点。`eval.ts` 和 `tree.ts` 已有来源解析、记录品牌、问题定位和截断机制，应优先复用这些机制，不另建一个默认节点引擎。

## Goals / Non-Goals

**Goals:** 在同一个只读求值器内提供明确的节点契约、精确的地址、可追溯的值和可验证的工作流。每个阶段保持随附示例及手动导入 pack 可用。

**Non-Goals:** 不借机重做 pack API、脚本信任边界、图调度器或画布样式。支持单个转储映射内的读取，不实现页表或多段地址空间。

## Decisions

### 1. 用同一份注册元数据决定新增入口

为定义声明是否接受跟随地址及目标端口。节点库和快速添加复用通用清单；跟随入口按端口能力筛选。仅供上下文使用的能力不可借类别名称自动进入所有列表。禁用的 pack 仍沿用已有规则。

第一阶段移除固定模板入口，并将 PRP 展开逻辑移到 NVMe 示例 pack，更新随附蓝图和生成脚本；无替代项的通用节点暂留。标注作为画布工具保留，现有共享常量和表达式作为辅助操作保留，不和类型转换或地址读写混用。相较于隐藏旧节点，直接移除已替换定义不积累无用兼容层。

### 2. 整数、地址、边界各自有明确定义

- 在新节点路径用精确整数承载地址和整数值（运行时用 `bigint`，文档字面量用字符串）；浮点独立处理。地址带所属映射，以「资产 ID + 映射基址」区分同一份字节的不同映射，不依赖文件名。新基址以精确文本记录。
- 不把基于 `number` 的旧 pack API 整体改成 `bigint`。精确地址先与映射基址相减并校验整个读取区间，再把已证明安全的文件内偏移交给字节视图；检查器和导航保留原绝对地址。地址线沿现有图结构传播来源，读前用解析得到的来源校验地址上的映射，不因读到地址值而切换数据源。需要与旧端口互操作时，只在无损且含义明确的地方适配，其余给出可定位诊断。
- 换算地址以源基准或显式输入地址为起点，两种模式分别暴露偏移或下标与步长。允许负字节偏移，不允许负池下标或非正步长；结果超出无符号 64 位地址范围时拒绝。普通整数在接到明示语义的输入时被绑定为该用途；已标记的地址、偏移和下标之间不做隐式转换。换算不读取，也不把地址在映射外当作算术失败。
- 有来源的字节范围用独立类型表示半开区间 `[start, start + length)`，引用已有资产；它作为来源时是值依赖。下游可进一步缩小范围，但不能扩大，失效或冲突时不回退。裸 `bytes` 和字符串作为来源仍是基址为零的镜像。固定长度按要求完整读取；空范围可以存在，但不允许读出一个字节。

比起给旧数字端口加显示提示，这能在接线与求值时阻止误接；比起把现有内存和 pack API 整体换型，兼容边界明确且更容易分阶段测试。

### 3. 读什么、怎么推进、怎么看，分别配置

- **读数值**与**读字符串**共用边界检查，不共享「万能读取」配置面板。字符串首版支持 ASCII、UTF-8、UTF-16LE/BE，按字节配置长度或上限，按编码单元识别零终止；不静默替换错误编码。**读指针**按指定的 4/8 字节和字节序解释一次读值，空值缺省为 `0`，可显式配置；空值判断优先于映射检查。诊断保留读位置和成功读出的原值，但不提供可用于继续读取的目标端口值，除非目标实际映射。偏移链仍是跟随地址的操作，其预览和生成的单步节点共用换算和读取规则，不把多级自动解引用并进读指针。
- 把进制、时间（显式时间单位）、枚举、标志预览与可选的 Hex/ASCII 预览归到检查器。直接在选中字节上试读或查看集合某项不写入图；要作为下游输入才生成对应节点或接线。位段要参与求值时，配置为读结构的具名字段。检查器可用上游提供的字节位置回到原始转储，不以预览文本重建数据。

### 4. 固定布局是文档数据，不是一个自动生成的 pack

布局在文档内共用，包含稳定布局 ID、总长度、缺省字节序、稳定字段 ID 和可编辑的名称、偏移、定宽类型与选填显示配置。首版支持定宽整数/浮点、定长字节/字符串及从固定存储单元提取的具名位段；整数可声明为偏移、下标或当前源中的绝对地址。位段可以共用底层字节，不因此认定布局无效。删除正在引用的布局或字段不能让其他布局或字段冒名顶替，缺失引用按节点报错。

读结构只解码一条记录。展开数组接标量读法或共享布局；遍历链表借用同一个布局解码器，再将 `next` 按绝对地址或池下标解释，结束值比较在换算前完成。用已见地址检测环，在读取预算内保留成功前缀；遇无效地址或环时不记成可继续的普通截断。复用现有结构树的按需展开、问题定位和截断语义。按下标取项只消费集合，不重新读取或在超限时选默认项。记录值沿用已登记记录的规则，避免将普通对象当作结构实例。

把字段布局复制到每个节点虽然改动小，但修正偏移后多个节点容易分叉。选择共享布局，并将其纳入保存/打开、缓存、撤销历史的同一文档快照。运行时求值结果不写入文档。

### 5. 断言给结论，校验和只给事实

校验和接完整字节范围，显式选择算法（首版 CRC-32/ISO-HDLC 与无符号 32 位字节累加），输出实际值；不为预览再造一个输出，也不自带一组比较端口。断言分别支持相等和闭区间约束，预期可写在节点上或接线；保留实际值/预期值、检查状态与来源定位。缺值、不可精确比较、源数据失败为「未能校验」；不允许把该状态当作普通 `false` 或用未连接缺省值覆盖断线后的结果。问题原因码与诊断文案分开。

## Risks / Trade-offs

- 精确地址只补读取而漏掉输入解析、跟随、高亮或序列化 → 用非零高位基址和低位非零测试同时覆盖这些环节；旧类型未支持时明确提示，不偷偷舍入。
- 数据源继承原先可能默认选首个文件 → 新节点在多映射中要求明确来源或唯一的来源链。显式范围保留现有来源优先级，新增值依赖环检测。
- 删除旧节点可能打断当前示例 → 完成替代项时更新随附示例；不为用户旧图新增迁移或兼容定义。
- 大集合和缺失字符串终止符造成高成本 → 所有读取/遍历有明确预算，预览限量不缩减真实输出；命中预算时公开截断状态，而非报成功。

## Migration Plan

1. 移除空壳 pack 入口，注册发现规则，将 PRP 移入 NVMe 示例 pack；跑通两个随附示例及导入。
2. 加入精确定位、基础读取与范围来源，先通过高位基址、来源冲突与失败状态测试，再替换对应默认节点。
3. 加入无脚本布局、集合、检查器解读与导航，完成后移除旧的展示型节点及只输出预览的数组节点。`element` 继续提供 pack 已知类型的字段展开。
4. 加入校验和及断言后移除旧比较和校验节点；补两条无脚本示例和浏览器回归。

旧图无须迁移。不删除已保存的数据；当前应用生成的蓝图、缓存及示例按同一文档契约读写。
