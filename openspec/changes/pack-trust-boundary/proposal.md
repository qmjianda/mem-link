# Proposal

## Why

蓝图把 pack 源码内嵌在 JSON 里，打开时用 `new Function` 编译执行。也就是说，打开一份他人制作的蓝图，等于执行他人的代码，且代码可以发起网络请求。这个议题真实存在，但它和本项目的核心用途——拖入 bin、按结构体解码、跟链表——没有关系。

它被从 `p0-baseline-and-correctness` 中拆出来单独排期，原因是：在核心链路还没跑顺的时候先做 CSP、导入授权、导出哈希清单，会把「能不能解析」的问题和「敢不敢打开」的问题混在一起，两边都推进缓慢。

当前仍按这个判断执行：本项目是本地使用的小工具，暂不为尚未发生的公开分享场景增加授权弹窗、哈希核对或额外运行时层。以下内容只保留为未来触发时的候选方案，不进入当前实现待办。

## What Changes

本轮不修改运行时行为。未来开始对外分享蓝图或引入多人协作时，再评估以下最小信任边界：

- **浏览器边界**：生产构建禁止网络请求；开发环境只放开 HMR 所需的连接。
- **导入提示**：打开陌生蓝图时先展示 pack 清单与风险提示，优先提供一次性启用本图全部 pack 的路径，不把逐个勾选强加给日常用户。
- **导出元数据**：导出物可带 pack 哈希与“包含可执行代码”声明，便于交接时核对。
- **一致性校验**：仅在启用上述导入流程后，用哈希变化触发再次确认；哈希不作为身份认证。

现有的 `PACK_DISABLED` 行为已经由当前代码提供，不属于本变更的新增任务。

## Capabilities

### New Capabilities

- `pack-trust`: pack 代码的执行边界、蓝图导入授权与离线约束。

### Modified Capabilities

（无）

## Impact

- **当前代码**：无。本轮不改 `index.html`、`vite.config.ts`、`src/bp/load.ts`、`src/bp/BlueprintApp.tsx` 或 `src/bp/doc.ts`。
- **未来触发后**：可能涉及上述加载、导出与构建边界，但应重新确认交互方案后再建实施任务。
- **兼容**：需要保留 `unsafe-eval`，因为本变更不替换 pack 的执行模型（仍是 `new Function`），只收窄它的能力。
- **触发条件**：开始对外分享蓝图、或引入多人协作时再做。仅自己使用本地文件时，这一层不产生收益。

## 不在范围

- 替换 pack 执行模型（Worker / 解释器 / WASM）。
- 签名与密钥管理：本变更只做哈希核对，不做身份认证。
