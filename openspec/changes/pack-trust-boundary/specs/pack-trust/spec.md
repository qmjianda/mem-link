# Spec Delta

## Purpose

明确谁能执行代码、何时执行、网络能到哪。目标是让"打开别人的蓝图"不再等同于"执行别人的代码"，并让离线承诺可被浏览器强制而不是靠代码自觉。

本规格是未来对外分享蓝图或引入多人协作时的候选契约；在该信任边界被明确启用前，当前本地小工具不要求这些额外交互和执行限制。

## ADDED Requirements

### Requirement: 导入蓝图默认不执行 pack 代码

当信任边界变更被启用后，打开外部蓝图时，系统 MUST 先列出其中 pack 的名称、来源与源码哈希，并 MUST 默认不编译、不执行这些 pack。只有用户授权启用后，相关节点才 MUST 开始求值。

#### Scenario: 打开陌生蓝图

- **GIVEN** 信任边界已启用，且有一份包含本机未见过 pack 的蓝图
- **WHEN** 用户打开该蓝图
- **THEN** 图结构与节点可见，相关节点标记为“pack 未启用”，且没有任何 pack 代码被执行

#### Scenario: 授权后恢复求值

- **GIVEN** 上述蓝图仍处于未启用状态
- **WHEN** 用户逐个启用所需 pack
- **THEN** 对应节点恢复求值，未启用的 pack 仍保持不执行

### Requirement: 运行时不得发起网络请求

当信任边界变更被启用后，应用 MUST 通过浏览器策略阻止页面发起任何网络请求，包括 pack 代码内的 `fetch`、XHR 与 WebSocket。被阻止的尝试 MUST 产生一条可定位到节点的问题。

#### Scenario: pack 内尝试联网

- **GIVEN** 信任边界已启用，且一个已启用的 pack 的节点代码调用 `fetch`
- **WHEN** 求值该节点
- **THEN** 请求被浏览器拦截，节点出现原因码为 `NO_NETWORK` 的问题

#### Scenario: 正常解析不产生请求

- **GIVEN** 默认 NVMe 示例图
- **WHEN** 打开并完成求值
- **THEN** 浏览器网络面板无任何请求，功能与当前版本一致

### Requirement: 导出物必须声明可执行内容

当信任边界变更被启用后，导出的蓝图与报告 MUST 包含所含 pack 的哈希清单与“包含可执行代码”的声明。导入方 MUST 能据此核对来源。

#### Scenario: 导出蓝图附带清单

- **GIVEN** 一张包含两个 pack 的图
- **WHEN** 用户导出蓝图
- **THEN** 导出物的元数据包含两个 pack 的哈希与可执行声明

#### Scenario: 哈希不一致时要求重新授权

- **GIVEN** 导入文件中记录的 pack 哈希与当前源码不符
- **WHEN** 用户打开该文件
- **THEN** 系统提示不一致，并要求重新授权后才执行
