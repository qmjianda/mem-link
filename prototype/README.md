# 结构设计器 · 可点击原型

这是 `visual-structure-designer` 的独立交互原型，用来确认“独立页面 + 直接操作”的手感。它不是生产实现，不读取也不写入项目文档。

## 打开

直接双击 `structure-designer.html`，或在仓库根目录运行：

```bash
python3 -m http.server 8080
```

然后打开 <http://127.0.0.1:8080/prototype/structure-designer.html>。

无构建步骤、无依赖、无网络请求。

## 建议试这几件事

1. **字节视图**
   - 从左侧把 `u32` 拖到空白字节，或点击类型卡片后再点空白格。
   - 拖动 `count` 字段：它会从“自动”变成“锚定”，底部出现新偏移。
   - 拖动 `string` 字段的右边缘改长度。
   - 选中 `entries`，点右侧「进入子布局」；用面包屑返回。

2. **位视图**
   - 顶部切到「位」。
   - 拖动 `mode` 位域条；拖左右边缘改位宽。
   - 把 `active` 拖到 `kind` 上，制造一次位域重叠，观察红色标记和底部统计。
   - 改「存储」宽度；如果成员放不下，会拒绝并说明原因。

3. **自动 vs 锚定**
   - 选中一个虚线字段，点「锚定到 0x…」。
   - 再点「恢复自动」，观察它回到声明顺序。
   - 这里没有“自动/手动模式”开关；只有字段自己的 `at` 状态。

4. **共享布局**
   - 左侧切到 `Entry`，改字段名；再回到 `Header` 看嵌套字段和外层长度同步。
   - 点「被引用」里的父布局，直接跳回去。

5. **入口与退出**
   - 点右上「完成」→「模拟返回蓝图」，看到一个简化的蓝图背景。
   - 在蓝图里点「结构设计器」或节点上的「编辑结构」，回到当前设计状态。

6. **撤销 / 导出**
   - 任何拖拽、改名、位域调整都可以 `Ctrl+Z` / `Ctrl+Shift+Z`。
   - 点「导出」查看即将写回文档的 `BinaryLayout[]` JSON。

## 原型里已经体现的决策

- 编辑结构是**独立全屏页面**，右栏只保留“选择 + 摘要”。
- 画布和表单编辑的是**同一份 `BinaryLayout`**，没有第二套模型。
- 字节视图和位视图是同一结构的两个投影，选中状态联动。
- 自动字段拖动后**明确锚定**，不引入模式开关。
- 位域组共享存储单元；位域重叠、字节重叠都会标红。
- 结构嵌套只进入子布局，不画任意节点连线；结构是树，不是通用图。
- 设计器只编辑文档布局；pack 类型仍是根结构或 `layoutType` 引用。

## 原型没有做的

- 不持久化，刷新即回到示例数据。
- 不接入真实 `doc.layouts`、撤销历史、求值器或 pack 编译。
- 不实现 C 声明导入、pack 导出源码、模板库、完整键盘导航。
- 蓝图背景只是入口示意，不是完整画布。

## 下一步

如果手感认可，正式实现会复用现有的 `BinaryLayout`、`compileLayout`、`commit` 和 `StructureRegistry`，不新增文档格式；设计器只作为 `doc.layouts` 的另一种编辑视图。
