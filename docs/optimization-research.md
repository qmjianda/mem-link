# mem-link 商业化优化方向调研

> 调研范围：ComfyUI（节点图引擎）、ImHex（模式语言 + 内容生态）、Nybble（schema 驱动的二进制浏览器）三个参照物，以及 IDA / Binary Ninja / Ghidra / Volatility / MemProcFS / 010 Editor / Kaitai Struct 的商用基线。
> 时间基准：2026-11。价格与版本以官网为准，本文只做量级参考。
> 本文只做方向与方案论证，不涉及代码实现。

---

## 0. 结论先行

五条判断，按重要性排序：

1. **你现在最值钱的资产不是"节点画布"，而是"图 = 可执行的假设"。** 画布本身不稀缺（ImHex 有节点式数据处理器、ComfyUI 有画布、Cascade 之类工具满地都是）。稀缺的是：一个假设画在图上，立刻能被字节验证，且验证结果可导出、可复现、可交接。所有优化都应该围绕这个闭环，而不是围绕"再多几种字段类型"。

2. **三个参照物里，ComfyUI 只有三分之一值得抄。** 值得抄的是执行引擎的三件工程小事（输入签名缓存、节点注册表、工作流资产化），不是"万物皆节点"。ImHex 值得抄的是多数据源抽象和内容商店。Nybble 值得抄的是一份非常诚实的 schema 表达力清单，加上"覆盖率"这个产品指标。

3. **商用化的第一道墙不是功能，是信任模型。** 当前 pack 是 TypeScript 代码，经 Sucrase 去类型后由 `new Function` 执行；而蓝图 JSON 里内嵌了 pack 源码。这意味着**打开同事发来的一张图，等于执行他的代码**。这一条过不了企业安全评审，后面所有功能都无意义。

4. **第二道墙是性能模型。** 现在是主线程、全量重算。RE 场景的输入动辄 1–32 GB 的 dump，全量重算在交互上不可接受。ComfyUI 用一条缓存策略把迭代时间压掉 40–60%，这条经验对 mem-link 的收益更大，因为改常量、改基址是最高频操作。

5. **第三道墙是交付物。** 没有 CLI、没有报告、没有 diff、没有断言，工具就停留在"个人探索"，进不了团队流程，也就没有预算科目。企业买的从来不是"能不能看"，而是"能不能复现、能不能审阅、能不能批量"。

一句话定位建议：**mem-link 是"内存/固件地址空间里的结构图编辑器"——不是文件格式查看器，也不是反编译器。**

## 1. 现状盘点

基于仓库事实（`src/` 约 1.69 万行 TS，React 18 + Vite，单文件产物约 685 KB，18 个内置节点，纯 DAG）。

### 1.1 已经领先于同类的部分

这几项是真实差异化，别在重构中丢掉：

| 能力 | 为什么稀缺 |
| --- | --- |
| 跟随地址（双击端口 → 选类型 → 自动新建 + 连线 + 居中） | ImHex / Nybble / 010 都要手动改偏移再重新应用模板 |
| 多级指针"偏移链"一次成图（含逐级实时预览、越界即禁止提交） | 同类工具里几乎没有等价物，这是逆向里最痛的一步 |
| hex ↔ 画布双向定位（点字节反选字段、点字段高亮字节、hex 里点字节直接"在此解析"） | ImHex 有字段↔字节联动，但没有"从字节发起一次新的解析链" |
| 数据源沿连线继承（不必每个节点接 File） | 图规模能压住的关键设计 |
| 断链不中断求值（`valid=false` 但仍给出真实读值） | 比"整图报错"成熟，是工程品味的体现 |

**结论：交互层已经是"能卖"的水平，引擎层还停在"能跑通"。** 后续投入应该 7:3 偏向引擎与可交付物，而不是继续加交互细节。

### 1.2 商用基线差距

| 维度 | 现状 | 商用基线（竞品最低要求） | 差距等级 |
| --- | --- | --- | --- |
| 执行模型 | 主线程、全量重算 | 增量求值 + 可中断 + 预算 | 高 |
| 大文件 | 单 ArrayBuffer，列表上限 4096 | mmap / 分页 / 多 GB 秒开 | 高 |
| 数据源 | File / Buffer 两种 | 磁盘镜像、分区、进程地址空间、远程只读 | 高 |
| 安全模型 | pack 即代码，蓝图内嵌代码 | 声明式优先 + 显式授权 + 签名 | 高 |
| 表达力 | 无 union tag 判别、无 varint、无 repeat-until | Nybble 级 schema | 中高 |
| 自动化 | 无 headless / 无 CLI | CLI + 退出码 + CI 断言 | 中高 |
| 可交付 | 导出图 JSON | 报告（HTML/PDF）+ diff + 断言结果 | 中高 |
| 生态 | pack 靠手动导入 | 注册表 + 版本 + 签名 + 离线源 | 中 |
| AI | 无 | MCP server（2026 已成行业默认接口） | 中 |

## 2. 三个参照物的机制拆解

### 2.1 ComfyUI：抄引擎，别抄形态

**做对的三件事（值得迁移）**

1. **缓存键 = 输入的祖先链签名，而不是节点自身。** 它的 `CacheKeySetInputSignature` 哈希的是"这个节点收到的全部上游输入"，所以上游没变，整条下游分支直接命中缓存。效果是改末端参数时迭代时间下降 40–60%。
   - 对 mem-link 的映射：现在是"改一个常量 → 全图重算"。改成祖先链签名后，改 `BASE` 常量只需重算下游。**这是投入产出比最高的一项改造。**
   - 具体难点：buffer 不可内容寻址。方案是 `(fileId, version, 采样页哈希)` 三元组做键，配一个"强制失效"按钮。

2. **节点注册表 + 版本化节点 API + 双 ABI 共存。** 第三方扩展不修改核心；新老两套节点接口（`INPUT_TYPES` 与新版 class API）在同一调度器里并存。
   - 映射：你的 pack 就是节点包，现在没有版本号、没有能力声明、没有兼容性检查。图一升级就静默坏掉，这是生态化的前置障碍。

3. **工作流 JSON 是"可 diff 的资产"，并且内嵌到产物里。** 生成的 PNG 里带完整工作流，拖回画布就能复现。这一招同时解决了传播、复现、信任三件事。
   - 映射：**把蓝图内嵌进导出的报告 HTML**——别人打开报告，除了看到字段树和字节，还能一键把整张图恢复出来继续查。这是你"单文件"能力的最佳用途，成本极低，传播价值极高。

**做错的三件事（必须避开）**

- `custom_nodes` 在服务启动前执行任意代码，装了节点就等于授予启动期 RCE；官方只能靠"全部禁用 + 白名单"兜底。
- 依赖不锁版本，官方自己承认"相隔一个月的两次安装不是同一个安装"，外加 6 万节点（官方口径；早期口径 2000+）无治理。
- 节点粒度过细导致图膨胀，"万物皆节点"在 RE 场景不成立——RE 的组合爆炸在**布局（schema）**，不在**流程**。mem-link 的图天然比 ComfyUI 小一个数量级，这是优势，别学它把类型也拆成节点。

### 2.2 ImHex：抄数据源与内容商店，别抄性能

**做对的**

- **多数据源抽象**：文件、裸磁盘与分区、GDB server（读运行中进程/嵌入式 RAM）、进程地址空间、SSH/SFTP、Intel HEX、Motorola SREC、Base64、UDP 包。这是它场景宽的根源——同一个解析器能对着"文件"和"活着的内存"两种源工作。
- **结构即视图**：模式语言解析出的字段直接覆盖在高亮字节上，还能把值可视化成图像、音频、坐标、时间戳。
- **Content Store**：模式库、库、编码、主题、YARA 规则在应用内一键更新，而不是让用户去 GitHub 翻仓库。
- **triage 先行**：magic 检测、字节分布/熵图、加密压缩区识别、YARA、内建 Capstone 反汇编。它先帮你"找到值得解析的地方"，再谈解析。

**做错/受限的**

- 百 MB 以上体验明显下降，几 GB 基本劝退（有分页视图，但解析仍是全量语义）。
- 强依赖 OpenGL 3.0，软件渲染版流畅度差；macOS 只支持 15+。
- GPLv2（`libimhex` 与 UI 插件库为 LGPLv2.1）——注意：**如果你考虑复用它的模式语言引擎，LGPL 边界允许动态链接进闭源产品，但会把你和它的数据模型焊死。建议先不复用，只借设计。**

**对 mem-link 的启示**：数据源广度是"能不能进客户现场"的门票；而"解析大文件不卡"恰恰是 ImHex 的软肋，是你的机会窗口。

### 2.3 Nybble：抄表达力清单与产品指标

Nybble（Rust + Tauri，AGPLv3，2026 年发布）是这三个里和 mem-link 最像的：schema 声明布局 → 实时重解析 → 字段与字节双向高亮。

**它做对的关键点**

- **schema 表达力覆盖了"真实格式会做的事"**：tag 派发 union、变长整数（LEB128）、每字段字节序、内联变换（xor / rolling xor / zlib / gunzip）、`check crc32 over(range)`、`repeat T until`、字节模式前瞻、指针（在别处读一个字段当偏移）、条件字段与计算字段、按 magic 自动选模式。
- **覆盖率（explained %）**：每次解析都报告"这份文件被解释了多少"，未解释区域在地图上着色，可"跳到下一个空洞"。这是把"我知道我不知道什么"做成了产品指标——也是最好的 AI 验证奖励函数。
- **shape hints**：对还不理解的区域给出形状建议（重复记录及其 stride、偏移表、字符串池、padding）。
- **CLI 与退出码**：`0` 匹配、`1` 不匹配/校验失败、`2` 用法错误；`--min-coverage 99` 直接进 CI，"当 schema 不再能解释这个文件时让流水线失败"。
- **工程选择**：mmap + 只渲染可见行，多 GB 秒开。

**它的软肋**：定位在"线性文件"，没有地址空间概念——没有多段基址、没有池下标、没有 PTM/PRP 这类跨区域跳转。**这正是 mem-link 的空位。**

### 2.4 机制映射总表

| 参照物 | 值得迁移的机制 | 明确不学的部分 | 对 mem-link 的落点 |
| --- | --- | --- | --- |
| ComfyUI | 祖先链签名缓存、注册表 + 版本化 API、工作流内嵌产物、App Mode | 万物皆节点、启动期任意代码、无锁依赖 | 引擎层 P0，生态层 P2 |
| ImHex | 多数据源（磁盘/进程/远程）、结构即视图、内容商店、triage 工具箱 | 全量解析大文件、GPU 强依赖 | 数据层 P0，生态 P2 |
| Nybble | schema 表达力清单、覆盖率、shape hints、CLI + 退出码、mmap | 只做线性偏移、无地址空间 | 语言层 P1，交付层 P1 |

## 3. 定位：空位在哪

把市面上的工具按两个轴摆开：**"线性文件偏移 ↔ 地址空间/指针图"** 与 **"已知格式 ↔ 未知/私有格式"**。

- 010 Editor / ImHex / Nybble / Kaitai Struct：线性偏移 + 未知格式（左下象限，人最多）
- IDA / Binary Ninja / Ghidra：地址空间 + 代码语义（右下象限，但对象是"代码"不是"数据结构"）
- Volatility 3 / MemProcFS / Volexity Volcano：地址空间 + **已知**操作系统结构（右上象限，靠 profile/符号表吃饭）
- **mem-link：地址空间 + 未知结构（左上偏右的空位）**

这个空位对应的人群很具体：固件/嵌入式（NVMe、U-Boot、RTOS 堆）、驱动与内核、游戏与主机内存、DFIR 里的私有结构、芯片验证的寄存器映射。他们的共同痛点是：**"我知道这块内存里是链表，但 next 是池下标、还有三个基址，hexdump 看不出形状。"** 这句话就是产品的 slogan。

对应地，功能优先级应该被这个定位约束：

- **地址空间模型 > 字段类型数量**（多段、多基址、虚拟↔物理、页表遍历）
- **寻址与展开策略 > 布局描述**（布局交给 schema，图只负责"去哪儿、怎么展开、怎么校验"）
- **可验证性 > 表达力**（一个能被 checksum 否证的粗糙模型，胜过一个无法验证的精致模型）

## 4. 六个优化方向（按杠杆排序）

优先级用"影响面 × 不可绕过性 ÷ 成本"排序。

### P0-1 信任与安全模型

**问题**：pack 是代码；蓝图内嵌 pack 源码；`new Function` 执行；CSP 需要放开 `unsafe-eval`。打开别人的图 = 执行别人的代码。

**方案（三层执行模型）**

| 层 | 形态 | 能力 | 默认策略 |
| --- | --- | --- | --- |
| L0 声明式 | 纯数据 schema（布局、字段、校验、展开规则） | 覆盖 80% 场景 | 直接执行，无风险 |
| L1 表达式 | 受限 AST（算术、位运算、比较、条件），非图灵完备 | 覆盖 15% | 直接执行，可静态分析 |
| L2 脚本 | 用户代码（现有的 `calcNode.run`） | 覆盖 5% | 需显式授权 + 沙箱 |

配套要求：
- 打开外部蓝图时，L2 段默认**不执行**，先展示"此图要求执行脚本（来源/哈希/权限）"，用户逐个授权。
- 能力声明：`read-only` / `exec` / `network`（网络默认永久关闭，与内网定位一致）。
- pack 锁文件：版本号 + 内容哈希 + 依赖清单；企业可配白名单与私有源。
- 长期把 L0/L1 的执行迁到 Rust/WASM 核心，则浏览器侧可以彻底摆脱 `unsafe-eval`——这是企业评审最容易过的一句话。

**验收**：打开陌生蓝图零代码执行；关闭 L2 时 CSP 无需 `unsafe-eval`。

### P0-2 求值引擎：增量、可中断、有预算

**方案**

1. **输入签名缓存**：节点缓存键 = 上游祖先链签名 + 自身配置 + buffer 版本。改常量只重算下游。
2. **拓扑调度 + 脏标记**：把"全图求值"变成"收集脏节点 → 按拓扑序求值"，天然获得进度显示与取消能力。
3. **预算与降级**：节点数、读取字节数、耗时三个上限（可配置）。超限时输出"部分结果 + 明确标注哪一段被截断"，绝不静默截断（你现在的 4096 上限就是静默的，应改为图上可见的"截断标记 + 一键继续"）。
4. **环检测升级为环可视化**：现在环变成问题条目。更好的做法是把环当成**发现**——显示入口地址、环长、周期；固件里的自环、双环、脏环本身就是情报。
5. **分层求值**：寻址层（便宜、必算）与呈现层（贵、可懒算）分开。字段树、hex 高亮、缩略图按需计算。

**验收指标**：改单个常量 P95 重算 < 50 ms；10 万字段树滚动 60 fps；4 GB 镜像打开 < 3 s（需配合 P0-3 的 mmap）。

### P0-3 数据源与地址空间模型

**问题**：只有 File/Buffer 两种源，场景被锁死在"已经落成文件的东西"。

**方案**：抽一层 `AddressSpace`（段表 + 页表 + 读写钩子 + 版本号），所有节点只面对它，不面对文件。之上再叠四种源：

| 源 | 用途 | 难度 |
| --- | --- | --- |
| 文件 / 内存块 | 现有 | 已有 |
| 磁盘镜像 + 分区表（MBR/GPT）+ 只读 FS 定位 | 固件、取证 | 中 |
| 崩溃转储 / 原始内存镜像（raw / LiME / minidump） | DFIR、内核 | 中高 |
| 远程只读（GDB stub / SSH / 串口） | 嵌入式现场 | 高 |

同时把"池下标"问题通用化：**段基址 + 重定位表（module base + RVA）** 是内置节点之外最该有的一等概念。你现在靠 pack 里的 `idxToAddr` 函数解决，应该升级成"地址空间声明"——声明一次，全图复用。

**验收**：同一张图能对 raw dump、minidump、磁盘分区镜像三种源复用，只需切换数据源。

### P1-4 语言与表达力

按 Nybble 的清单补齐，这是"能不能覆盖真实格式"的分水岭：

| 缺口 | 现状 | 建议 |
| --- | --- | --- |
| union tag 派发 | 未做（README 已列） | 一等公民：tag 值 → 分支类型，图上显示命中分支 |
| 变长整数（LEB128 / varint） | 无 | 内置字段类型 |
| 条件字段 / 计算字段 | 只能写进 transform | 声明式 `if` 与字段间算术 |
| repeat-until / while 前瞻 | 只有 `listNode` 的 next | 迭代节点（带边界与终止证明） |
| 内联变换/解压（xor、zlib、gunzip） | 无 | 变换节点输出新 buffer，可接下游（这是"解析压缩流"的关键） |
| 校验和断言 | 有校验节点，但是"算"不是"验" | 升级为断言：`check crc32 over(range)` → 图级绿/红 |
| 每字段字节序 | 已有（`endian` 覆盖） | 保持 |
| 跨 pack 类型引用 | 未做 | 类型导入 / 标准库 |
| 数组 stride 自动推断 | 无 | 结合 shape hints，从重复模式里猜 stride |

**互操作是捷径**：支持导入/导出 Kaitai `.ksy`、010 `.bt`、ImHex `.pat`、Nybble `.schema`。理由很直白——世界上已经有大量现成格式描述资产，要求用户重写一遍是最贵的获客成本。导出则让 mem-link 成为"能产出标准资产"的工具，反过来增加采用理由。

### P1-5 可交付物：CLI / diff / 报告 / 断言

这是从"工具"变成"流程组件"的一步，也是采购预算的入口。

- **headless CLI**：把一张图和一份镜像跑成结构化输出（JSON），带退出码（0 解释通过 / 1 断言失败 / 2 用法错误）与覆盖率门槛。用途：批量跑固件、CI 回归、样本分诊。
- **diff**：同一张蓝图应用到两个 buffer，输出字段级差异 + 偏移漂移。用途：固件版本对比、补丁前后对比、两次 dump 对比。**这是被低估的高价值功能**——图结构不变、只换数据源，正是 diff 的天然形态，而 ImHex/010 的 diff 是字节级的，读不出语义。
- **报告导出**：单文件 HTML，含字段树、字节证据、文件哈希、断言结果、图快照，并把蓝图内嵌进去（学 ComfyUI 的 PNG 元数据思路）。用途：交付、评审、复盘、写进案件材料。
- **断言集**：每个节点可挂 magic/range/checksum 断言，图级汇总成一个"置信度"。这是可验证性的具体形态，也是后面 AI 环节的 ground truth。

**验收**：CI 里能对 100 个固件样本批量跑；失败能定位到具体节点与具体字节。

### P2-6 生态与 AI

**生态（顺序很重要：先治理，再开放）**

1. pack 注册表：语义化版本 + 锁文件 + 签名 + 能力声明。
2. 私有源优先：内网客户要的是"我们自己的格式库能从内部源更新"，而不是公共市场。
3. **格式即测试**：每个格式包附带样本与快照测试（Nybble 的每个内置解析器都有 snapshot test），解析结果变化必须显式确认。这一条能把"格式库质量"变成可度量的东西。
4. App Mode：把一张图折叠成一个表单（选文件 → 出字段表），分发给不学图的同事。ComfyUI 的 App Mode 是它从"玩家工具"变成"生产工具"的关键一步，mem-link 同理——**让分析师能产出"可分发的小工具"，是这类产品最强的传播机制**。

**AI（2026 的必答题，但不能是噱头）**

行业现状（2026-09 至 10 已成定局）：Hex-Rays 发布官方 IDA MCP Server 并在 9.5 内置 agent；Binary Ninja 的 Sidekick 5.0 是"主动式"的——后台自己找活干，配一个可编辑 Notebook，并对每条结论标 `draft / verified / rejected`；Ghidra 侧 GhidraMCP、ReVa 是社区标准配置。

mem-link 的位置很特殊，也应该很清醒：
- **不要做"AI 反编译"**。研究模型的指标是"能不能重编译运行"，不是"结构是否忠实"，这条路打不过也守不住。
- **要做"AI 提假设，引擎做否证"**。图天然是可执行的：AI 提出一个候选结构/候选 stride/候选指针基址 → 引擎立刻算出覆盖率、校验和、越界情况 → 只有通过断言才升为 `verified`。这个闭环比任何"AI 反编译"叙事都硬，因为它可被证伪。
- 接口形态：MCP server，暴露 `follow_address` / `propose_type` / `verify_hypothesis` / `explain_node` 等少量高层工具（学 Hex-Rays 的 Code Mode 结论：一百个细粒度工具既慢又烧 token）。
- 部署：本地模型优先（内网、敏感样本），云端可选且默认关闭；每次 AI 调用在图上留痕（谁、什么模型、改了什么、是否 verified）。

## 5. 目标架构

一句话：**UI 与引擎解耦，引擎与数据源解耦，脚本与声明解耦。**

四层 + 两条约束：

1. **UI 层**：画布、检查器、hex、报告预览。只发命令，不直接算。
2. **命令层**：每个用户动作 = 一条命令（可序列化、可撤销、可脚本化、可回放）。这是能长出 CLI 与自动化的前提。现在的 UI 是直接改状态，导致"能用鼠标做的事，脚本做不了"。
3. **引擎层**：图 IR + 缓存 + 拓扑调度 + 预算 + 断言求值。纯函数，可脱离 UI 单测。
4. **核心层**：AddressSpace、解码、校验、变换，用 Rust 编译到 WASM，桌面与 Web 共用一份。
5. **数据层**：mmap / 分页 / 远程钩子。

两条约束：
- **一份核心，两个壳**：单文件 HTML（Community / 内网 / 取证机 / 靶场）+ Tauri 桌面（Pro）。不要放弃单文件——它是你唯一一个竞品完全没有的分发优势（ImHex 要装、Nybble 要装、IDA 要授权服务器）。
- **不要一次重写**：先把求值抽成纯函数并加缓存（改 20% 代码拿 60% 收益），再抽 IR，最后换 WASM 核心。反过来做会死在迁移里。

**空档**：$99–249 一次性个人版 / $499–899 商用席 / 企业按年。理由：mem-link 不是反编译器，不该按 IDA 定价；比 010 贵一档，必须靠"图 + 覆盖率 + 报告 + diff"说服。免费开源竞品（ImHex/Nybble）已经把"看字节"打到零价，所以**定价必须锚在"省下的时间"和"可交付的报告"上，不能锚在"能看"上**。

### 7.2 分层建议

| 层 | 内容 | 目的 |
| --- | --- | --- |
| Community（免费） | 单文件 HTML、离线、单图、无 AI、导出带水印报告 | 传播与信任，替你做市场 |
| Pro（个人） | 桌面版、CLI、批量、diff、报告、无限制图 | 主力收入 |
| Team | 共享图、评论、私有 pack 源、审计日志 | 从个人到团队的跳板 |
| Enterprise | 私有部署、SSO、签名策略、SLA、格式库定制 | 单价高，靠安全模型过关 |

### 7.3 许可与技术选择

- **核心闭源 + 格式开放 + 免费查看器**：用"免费看图/看图即恢复蓝图"做传播（对应 ComfyUI 拖图复现），用编辑器收钱。这是这类工具唯一被验证过的飞轮。
- 不要碰 AGPL 代码（Nybble）。`libimhex` 是 LGPLv2.1，理论上可动态链接，但会把数据模型焊死，**不建议复用，只借设计**。
- **离线/内网许可是你的差异化**：竞品几乎都需要联网激活或云账号；你的客户（内网、靶场、取证机、产线）恰好不能联网。这一条要写进销售物料第一页。

## 8. UI / 设计方向

现状（从 `docs/screenshot.png`）：暗色、三栏、青绿强调色、节点卡片 + 端口圆点；信息密度高、字号偏小、右侧检查器较挤、画布留白多但缺少"当前焦点"的锚。

### 8.1 设计主张

**画布是唯一焦点，其余面板都可折叠。** 绝大多数逆向工具是"面板的集合"，用户在一堆窗格里找东西；mem-link 应该反过来——任何时候画面只有一个视觉中心（当前解析链），其余都是按需展开的辅助。

三条原则：

1. **渐进披露**：概览（图）→ 字段（表）→ 字节（hex）。三层永远在同一个视口里对得上，但一次只强调一层。
2. **语义色，不做装饰色**：地址=蓝、越界/断链=红、未解析=灰、校验通过=绿、AI 提案=紫。颜色只承担语义，不承担风格。
3. **数字必须等宽、必须对齐、必须有单位**：`0x1200`、`3072 B`、`6 页`。逆向工具的专业感来自对齐，不来自阴影。

### 8.2 具体建议

- **双主题对等**，不是"暗色为主 + 浅色凑合"。竞品几乎全是暗色；浅色主题在白天办公室、投影评审、打印报告、法证复核四个场景是真实需求，也是低成本差异化。
- **补三个缺失的可视化**：覆盖率条（本次解析解释了缓冲区的百分之多少）、置信度徽章（断言通过数 / 总数）、截断标记（哪里被预算截断、一键继续）。
- **检查器表格重排**：现在字段名/值/类型挤在一行。建议"名称左对齐、类型弱化、值右对齐等宽"，斑马纹只用于隔行不用于分组，悬停即高亮字节（已有），点击锁定（已有）——这套交互已经对了，只差排版。
- **动效只服务定位**：居中飞行、高亮脉冲、跟随地址时的视口过渡。不做装饰性动画——专业工具的"高级感"来自克制。
- **报告是 UI 的一部分**：导出的 HTML 要和主界面同一套 token（同一字体、同一语义色、同一间距系统）。客户看到的第一份"设计"往往是报告，不是应用。

## 9. 风险与"不做"清单

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 单文件天花板 | 浏览器内存上限、无 mmap、无原生能力 | 桌面壳并行，单文件保留为 Community |
| 安全事件 | pack 代码执行一旦被利用，商用信誉归零 | P0-1 优先，三层执行模型 |
| 生态冷启动 | 没有格式库就没有留存 | 先做 20 个高频格式（NVMe、ext4、PE、SQLite、LZ4、SquashFS…）+ 互操作导入 |
| 免费替代 | ImHex/Nybble 免费且活跃 | 差异在"地址空间 + 可验证 + 报告 + 内网" |
| AI 成本与合规 | 敏感样本不能出境 | 本地模型优先，云端默认关，全链路留痕 |
| 法务边界 | 工具被用于破解/绕过 | 明确 EULA：禁止绕过 DRM/授权；不提供破解工作流 |

**明确不做**（守住范围，比加功能更重要）：

1. **不做反汇编/反编译**。打不过 IDA/Binja/Ghidra，且会把团队拖进指令集与 ABI 的无底洞。需要时通过 MCP 对接它们。
2. **不做整体克隆与破解协助**。法律边界，也是品牌边界。
3. **不追大而全的节点市场**。治理成本高于收益，先把 20 个格式做到"有测试、有覆盖率、能过 CI"。
4. **不做云协作（早期）**。你的客户首先要求"数据不出机器"。
