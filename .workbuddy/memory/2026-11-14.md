## 蓝图工具两项逻辑改造

需求：解析节点不再需要逐个接 `buffer` 线（应能自己溯源最初的 File 节点）；链表/数组/结构体的每个元素都要能作为独立 out 端口连线。

实现要点：
- `src/bp/eval.ts`：新增 `trace/traceInner/sourceOf`，按「检查器手动 sourceId > 旧图 buffer 边 > 沿入边向上游追到的 File > 图里第一个 File」解析数据源；`BPResult.sources` 记录每节点实际文件与方式，冲突时告警。解析节点 `portsFor` 去掉 `buffer` 输入。
- 动态端口：`dynamicOf(view)` 为 list/array 每个元素生成 `elem:i`（instance，值 = 带 mem 的 InstanceView），为 struct 的 `array`/`record` 字段生成 `elem:字段:下标/成员`。求值结束统一发布端口和值（result.ports 含动态端口，连线校验改用它）。
- `canConnect` 允许 `instance -> number`（取元素地址），`toNumber` 支持 InstanceView；`Element` 内置节点新增 `instance` 输入，可直接接元素。
- `src/bp/Canvas.tsx`：元素端口渲染成可点选的行（默认 8 个 + 展开全部，已连线的端口折叠时也保持可见），行右侧就是可拉线的圆点。
- `src/bp/doc.ts`：`打开图` 时把旧 `buffer` 边迁移成 `params.sourceId`，避免悬空连线；evaluator 仍兼容未迁移的旧边。
- 同步更新 Inspector（数据源下拉 + 来源展示）、Palette、styles.css、README、docs/description-format.md、samples/demo.blueprint.json、BlueprintApp 初始图、tests/bp.test.ts（新增 10 个用例）。
