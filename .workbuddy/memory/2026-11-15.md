## 蓝图：File 可连 + 数据源依次继承 + 输入回显（推翻 11-14 的「删掉 buffer 端口」方案）

用户反馈：File/Buffer 不能与其它节点连线，成了空节点；期望「文件连 header、entry 连 header，就隐含使用 header 的文件，依次继承」。上一版把解析节点的 `buffer` 输入删掉是方向错误。

### 最终模型
- File 是真正的数据源起点，输出 `buffer` / `base` / `size`，都能连线。
- 所有非 File 非 Number 节点都有**可选**的 `buffer`「数据源」context 输入（`PortSpec.context = true`，画布上是虚线圆点）。接上=直连该文件；不接=沿任意入边向上**逐级继承**上游节点的文件。
- 溯源优先级：`params.sourceId` 手动 > `buffer` 显式连线 > 沿其它入边递归继承 > 图里第一个已载入 File。
- `SourceInfo` 增加 `fileId` / `chain`（继承链）/ `via`（来源边）/ `candidates`，冲突时告警。
- 关键边界：trace 用 `root` 标记，只有被解析的节点本身能套用默认文件；中间跳数中，**纯常量节点（Number）不携带文件上下文**（`carriesContext` 判断），但解析节点即使孤立也携带它自己绑定的默认文件，否则「孤立链表 → 下游」会继承失败。
- `canConnect`：任意 → `buffer` 都允许（含义是继承上游文件）；`instance → number` 仍允许（取元素地址）。

### 输入回显
- `BPResult.inputs: Map<nodeId, Record<port, InputValue>>`，`InputValue` 含 value/display/wired/from/inline/invalid。
- `evalBody` 开头预读所有声明输入，保证每个端口都有解析值。
- 画布与检查器：连线后输入框变成只读的上游真实值（地址按 `0x…` 显示）+ 来源提示 + `×` 断开；断开后恢复原来手填的 inline 文本。

### 其它
- `doc.ts` 撤销上一版的「buffer 边迁移成 sourceId」逻辑，改为原样保留边、只丢弃端点不存在的悬空边。
- Canvas 支持双向拉线、点同端口取消、点空白取消、拖线时兼容端口高亮；选中边在检查器显示当前值/类型/是否数据源边。
- 默认图和 `samples/demo.blueprint.json`：`File.buffer → Header.buffer → head → List.address → elem:0 → 另一个 Header.address`，一条完整继承链。
- 改动文件：`types.ts` / `eval.ts` / `Canvas.tsx` / `Inspector.tsx` / `BlueprintApp.tsx` / `Palette.tsx` / `doc.ts` / `styles.css` / `tests/bp.test.ts` / 示例 / README / description-format.md。

- vitest 在本机仍跑不起来（pnpm junction 不可读 + 盘符大小写模块实例分裂）。等价验证用 esbuild 打包独立脚本：入口 import 真实 `eval.ts` / `load.ts`，`packages: 'external'` 绕开 `.pnpm` 里损坏的链接，node 直接跑，**25 项断言全通过**，含真实 `demo.blueprint.json` 端到端。正式用例已写进 `tests/bp.test.ts`，需在正常 shell 跑 `pnpm test` 复核。

## BugFix：点击端口起线首帧蚂蚁线指向世界原点 (0,0)

用户反馈：按下端口不拖动时，pending 虚线错误地连到画布世界原点，一移动就恢复。

### 根因（与最初猜测不同，以磁盘代码为准）
- `Canvas.tsx` 的 `startConnect` **有**设置 mouse，但用了错误锚点 `toWorld(r.left, r.top)`（画布宿主左上角），换算后恒等于 `(-view.x/view.k, -view.y/view.k)`，紧邻世界原点；叠加 `mouse` 初值 `{x:0,y:0}`。
- pointerdown 不派发 pointermove，`onPointerMove` 里的 `setMouse(toWorld(e.clientX, e.clientY))` 才是唯一正确写入，所以「按下不动」期间一直错。

### 修复（仅 `src/bp/Canvas.tsx`，4 处）
- 3 处端口 `onPointerDown`（输入端口含数据源口、静态输出口、动态元素端口）透传 `e.clientX/e.clientY`。
- `portDown` / `startConnect` 签名加坐标；起线时在同一次事件里 `setMouse(toWorld(clientX, clientY))` + `setPending(...)`，与 move 共用同一 `toWorld`/同一 `view` ⇒ 首帧零跳变；React 18 `createRoot` 自动批处理保证无「pending 已渲染、mouse 仍旧值」的中间帧。
- 三级兜底：rect 缺失/坐标非有限 → `findPort` 端口世界坐标 → `node.x/node.y`；渲染层 `if (!a) return null` 兜底不画线。
- 未改 `finishConnect` / 取消逻辑 / CSS / 求值器。

### 验证与环境更正（重要）
- `tsc --noEmit`、`vite build` 通过。
- **上面记的「vitest 跑不起来」已过时**：本机实测 `node node_modules/vitest/vitest.mjs run` 可跑，真实基线是 **4 个测试文件 65 用例**（session 3 / core 16 / pack 15 / bp 31），重跑 65/65 全通过。

### 架构（关键决策）

- `types.ts` 新增 `NODE_WIDTH` / `NODE_HEADER` / `dropPosition(world)`（光标落在标题栏、节点水平居中）；Canvas 的 `HEADER`/`NODE_W` 改为引用同一常量，落点计算有 4 个单测。

## BugFix：Element 端口固定显示 magic/head，没跟随实际元素

用户反馈内置 Element 组件的端点一直是固定的 `magic`/`head` 等，而不是接入元素的内容。

### 根因
`eval.ts` 的 `portsFor` 里 `case 'element'` 只用 `params.packId`/`typeId` 生成 `fieldPorts(type)`，**完全没用传入的 `view`**；而求值分支用的是 `item.fields`（真实元素）。Element 添加时 `typeId` 默认取第一个 pack 的第一个类型（demo 里正好是 Header），所以接 Entry 元素后端口仍是 magic/head/tail/count。`portsFor` 在生成结果端口时（约 474 行）其实已传 `view`，只是分支没用。

### 修复
- `portsFor` element 分支：有 `view.kind === 'element' && view.inst` 时用 `inst.fields` 生成端口（name 来自实际字段；type 优先按 `typeName` 找 TypeDef 再 `fieldPortType`，找不到用 `portTypeOf(value)`；label 取 `f.label ?? decl.label`）。未连线才回退 `params.typeId` 模板。
- 新增 `findTypeByName(typeName, packId, packs)`：实例只带 `typeName`，优先节点自己的 pack，再遍历所有 pack。
- `dynamicOf` 条件从 `view.kind === 'struct'` 扩到 `struct | element`，Element 也展开嵌套 `array`/`record` 成员端口；element 分支 outputs 追加 `dynamicOf(view).ports`（第一次漏了，测试抓到）。
- Inspector：已连线时不再显示 pack/type 选择器，改为「来自连线 / 类型 / 地址」+ 说明；未连线才显示模板选择器。
- Canvas 标题：Element 显示 `元素 · 实际类型`。
- eval 末尾加悬空边检查：端口随类型变化消失后，指向它的边报 `warn`「连线端点已不存在：a → b」，避免画布上静默消失。

### 验证
- tsc / vite build 通过；vitest 4 文件 **73/73**（新增 4 个用例：模板故意选 Header 接 Entry 元素断言端口为 Entry 字段、list+index 路径、未连线回退模板、Element 接带 array/record 的元素展开嵌套端口）。

## 下午（三）：多级指针连续跟随，主线程实现

用户选了「多级指针」。核心：跟随地址浮层里填一条偏移链，一次展开整条解引用链。

### 实现
- 新增内置节点 `ptrwalk` 指针步进（内置总数 3→19→20）：`base+offset` 处读 4/8 字节指针，输出 `address/target/valid`。
  - **断链语义**（这是设计决策，不是顺手）：读取地址越界 → `target=0, valid=false`；读到指针但目标越界 → `target=真实读值, valid=false`。不抛错，让链继续求值，把断点显示在图上。
- `builtins.ts` 加 `parseOffsetChain()`：支持 `+0x10, +0x24` / `0x10 0x24` / `16,-8` / 全角分隔，空串=单级。
- `FollowPicker` 加偏移链输入 + 指针宽度下拉 + **实时逐级预览**（`+0x10 → 0x1100 → 0x1400` / `最终 0x1400`）；预览报错时 Enter 不提交。
- `BlueprintApp.doFollow(item, offsets, width)`：n 个偏移 → n 个 ptrwalk 纵向排布（`target→base` 链式连线）+ 1 个解析节点，**一次 commit = 一条撤销记录**；自动避让已有卡片、居中到最后节点。

### 踩坑（1 个，且很有教育意义）
- 测试数据用 `bytes[off+i] = (v >>> (8*i)) & 0xff` 填 8 字节：`>>>` 的移位量**取 mod 32**，i≥4 时 `8*i mod 32` 回到 0/8/16/24，把低字节复制到高字节。期望 0x2000 实际读出 0x200000002000。**填 8 字节必须用 `BigInt(v) >> BigInt(8*i) & 0xffn`**。这也反过来证明了 ptrwalk 读的是真实缓冲区内容。
- 另一个语义澄清：断言时别把 `target`（真实读值）和 `valid`（目标是否越界）混为一谈；"读到指针但目标越界"时 target 是非零的。

### 验证
- `tsc` 0 错；`vitest` **244/244**（builtins 20 例：ptrwalk 单元 + parseOffsetChain + 两条端到端链）。
- `vite build` 704.34 kB / gzip 207.19 kB。
- `cdp-verify.mjs` **45/45**（新增 5 项：prp2 端口命中、浮层再开、偏移链预览显示 0x1100→0x1400、展开 2 节点 2 连线、步进 target 输出 0x1400）。
- CDP hover 修复：`button:'none'` + `buttons:0` 才会派发 mouseenter；`button:'left'` + `buttons:0` 是矛盾状态。

## 下午（四）：标注节点（图上便签），主线程实现

用户选了「标注节点」。目标：分析结论直接钉在图上、随图保存。

### 设计决策：内置节点路线，不做注释层

## 下午（六）：易用性收敛（节点合并 21 → 18），主线程实现

用户要求：提升易用性（简化流程/反馈/引导），**合并冗余节点**，保持功能范围与代码结构不变。

### 合并决策（先审查再动手，三个都是真冗余）
- `pointer`（指针解引用）⊂ `ptrwalk`（指针步进）：ptrwalk = pointer + offset；合并时给 ptrwalk **补 hex 位模式输出**，不丢能力。
- `bitwise` ⊂ `expr`：求值器操作符表 `& | ^ << >> ~` 与 bitwise 的 op 集合完全一致，bitwise 只是下拉封装。
- `float` ≈ `readint`：输入/输出结构相同；readint 改名「数值读取」，size 下拉加 f4/f8。
  - 注意：`NUM_SIZE_OPTION` 与 `SIZE_OPTION` 分开定义——arrayread 的宽度下拉不应出现浮点选项。
- `legacy` 字段（file/number/element）是死代码（Palette 从不过滤），整体删除。
- 21 → 18 个内置节点。

### 迁移
- `types.ts` 导出 `migrateNode()`；`parseDoc`（打开图）+ `deserialize`（旧缓存）两处入口统一调用。
- bitwise → expr 按 op 生成模板：`op:'<<'` → `formula:'a << b'`，a/b 参数值带入；float 的 size 映射 f4/f8；pointer 的 address → base、offset='0'。
- 测试口径修正：file/number/element 走求值器专门分支没有 `run`，注册表断言要显式排除这三个（原来靠 legacy 标记跳过）。

### 易用性（不加新功能）
- 空画布引导从一句话升级为完整操作提示（添加 / 双击端口跟随地址 / Ctrl+F / Ctrl+L / ? 快捷键）。
- hex 跳转框非法输入：红框 + aria-invalid + title 说明支持的格式。

### CDP flaky 修复（重要）
`mouseMoved` 若目标与上次位置相同，Chrome **不派发 mouseenter**——hover 类断言必须先移开再移入两步。实测 4 连跑全绿。

**真正的根因（产品级，比断言更重要）**：字段地址条原本插在表格**上方**，悬停/点选时插入内容把表格往下推 → `mousedown` 后鼠标命中点随之偏移 → `click` 落在地址条上，行内 `onClick` 不触发。这正是间歇性失败的来源，也是真实的产品缺陷（悬停时表格跳动）。**修复：地址条移到表格下方**，插入不推移上方内容。改完 5 连跑全绿。
另一个禁用词命中：命令 label「一键自动布局」→「自动布局」（与顶栏按钮、菜单一致）。

### 验证
- `tsc` 0 错；`vitest` **258/258**（新增迁移 5 例：pointer/bitwise/float/pack 原样/deserialize 集成）。
- `vite build` 712.02 kB（比合并前还小）。
- `cdp-verify.mjs` 62 项，4 连跑全绿（新增：节点库无旧节点名、含合并节点、清空画布后引导）。

## 傍晚：配置自动继承（少一步设置），主线程实现

延续「易用性收敛」主题，这轮做的是**去掉重复设置步骤**：再添加同类节点时，宽度/符号/字节序/指针宽度下拉自动沿用上一次的设置。

### 实现
- `builtins.ts` 导出纯函数 `inheritOptions(nodeId, nodes)`：找最近一个同类内置节点，只继承 `select` 类 options 中**与默认值不同**的项。
  - text 类输入（表达式/文本）不继承——避免把上一条公式带进新节点。
- 接入三个创建路径：`onAdd`（节点库单击/拖入/Ctrl+K 快速添加，都归于此）、`doFollow` 的解析节点、多级指针链的 ptrwalk（继承 endian）。
- 展开顺序是关键：`{ ...defaults, ...inherited, 显式参数 }`——显式参数（ptrwalk 的 pointerSize 来自浮层选择）永远最后展开，继承值不能覆盖用户当前明确的选择。
- 入口审查确认无其它多余步骤：QuickAdd 复用 onAdd；添加后自动选中（检查器立即就绪）；slice/text/checksum 的 length 已有合理默认（64）。

### 验证
- `tsc` 0 错；`vitest` **259/259**（新增继承 1 例：继承/排除 pack 节点/无同类/最近生效）。
- `vite build` 712.35 kB。
- `cdp-verify.mjs` **65/65**：React native setter 驱动受控 select（`HTMLSelectElement.prototype.value` setter + change 事件）验证「改 u16 → 再添加 → 自动 u16」链路。
